# 训练算法与样本效率：已有回答的CPU反事实

**2026-10-29研究优先级纠正：最终只按ACC@0.5选方法。奖励有差异不等于存在命中正负对；连续IoU增加活跃组不构成优先理由。新的严格命中统计与G2纠错分流见[修订分析](../2026-10-28-rl-reassessment/README.md)。**

**2026-10-29补充：** 本文旧B59统计保留，最新60—100步、实际分母与奖励幅度分析见[RL复核](../2026-10-28-rl-reassessment/README.md)。现役明确为`scale_rewards=none`，组标准差放大仅是假设性风险。连续IoU使新B活跃组32→159，但优势平方和仅增加8.43%，不能按活跃组数估计收益。G8→G2另有已证实的1/G缩放与估计器混杂，候选须先控制，不能直接启动后仅归因为少采样。

2026-10-28。用户要求寻找能大幅提速的结构或算法。此文讨论新算法候选，不改变正在继续的A/B550配置。所有CPU统计来自原B59的236组、1888个回答，覆盖227道不同题；不是新续训的实时结果，也没有运行新模型采样。

## 1. 比“每步多久”更深一层的问题

原A236组有54组奖励不同，B236组有49组奖励不同；两组约77%—79%的组不能提供组内相对奖励信号。仍存在KL正则梯度，不能把这些组叫作“完全没有梯度”或直接跳过而声称等价。B的236组均存在预测框差异，说明奖励相同并非模型始终生成同一个框。

原因有直接代码证据：[quant_grounding_reward.py](../../../tools/quant_grounding_reward.py) 的合法回答奖励为：

`1[IoU >= 0.5] + 0.2 * min(IoU, 0.5) + A专有的对比项`。

B的IoU达到0.5后奖励固定1.1；例如已记录的第一组，IoU从0.534到0.805变化，8答仍全部得到1.1。这个设计强调比赛命中阈值，不能仅因出现平台就称它是错误。但它确实不再鼓励已命中框的进一步精确定位，并且消耗采样来反复确认这类平台。

## 2. 本轮CPU复算

复算入口：[analyze_existing_rollouts.py](analyze_existing_rollouts.py)，汇总：[rollout-counterfactual.json](evidence/rollout-counterfactual.json)，逐题：[rollout-counterfactual-groups.jsonl](evidence/rollout-counterfactual-groups.jsonl)。每个G8组枚举全部G2/G4子集，无随机抽样误差。

“有信号”在本节仅指组内奖励不全相同，不代表梯度足够大、方向有益或最终成绩提高。

| 子集大小 | 原奖励有差异的组，期望/236 | 原奖励有差异比例 | 每100个回答的有差异组数 | 去掉IoU项上限后的有差异组，期望/236 |
|---|---:|---:|---:|---:|
| G2 | 24.61 | 10.43% | 5.21 | 227.50 |
| G4 | 37.81 | 16.02% | 4.01 | 230.86 |
| G8 | 49.00 | 20.76% | 2.60 | 232.00 |

反事实奖励保留命中项、非法惩罚，将`0.2*min(IoU,0.5)`改为`0.2*IoU`。当前代码和正在训练的奖励均未修改。

含义：

1. **G2值得试，但不是把8改2就已成功。** 固定同样236道题时，其回答数减少75%，有差异组约减半；每个回答对应的非零相对信号机会反而约翻倍。优势方差、训练归一化、题覆盖和最终收敛尚未得到证据。
2. **奖励饱和比回答重复更突出。** 去掉上限后G8有差异组49→232，G2也达227.5；这为小组配合连续几何奖励提供了本项目依据。差异可能只是很小的边框抖动；按组标准差归一化会放大小差异，不能把“非零”当作“有效”。若测试该方向，应保留命中阈值主项，并观察错误实例/阈值附近样本，而不是只看总体奖励方差。
3. **完整回答去重没有规模收益。** 1888答在各自题组内有1882个不同文本，仅6个重复（0.318%，5组）。文本相同还不保证原token ID完全相同；即使都能合并，也没有大幅提速空间。
4. **简单2→4→8自适应采样收益有限。** 若一出现奖励差异即停止扩组，否则继续到8，基于已有8答的随机排列期望只省10.62%的回答；约79%的饱和组仍会采满8。它改变估计器且可能增加多次生成启动成本，不值得先做复杂调度。

原回答平均22.878个生成词元。当前已经是短框输出，许多文献通过缩短长思维链得到的收益不适用于本轮。

## 3. 最值得落地的两个算法候选

### 候选一：小组GRPO与连续几何反馈

最小设计是先比较G2与G8，保持每步4道题、数据呈现顺序和原奖励不变；使用正确的原逻辑回答分母，不能让累积次数变化偷偷缩放梯度。之后仅在G2上加入不饱和IoU辅助项，便能分别回答“少采样是否够用”和“平台奖励是否限制少采样”。不用一次组合多个采样策略、回放缓冲、KL修改和新骨干。

G2保留GRPO组内基线，工程改动小。未共享前缀时，按每步同4题计算，生成及逐答前后向逻辑数量由32降8，存在接近4倍的主要工作量削减空间；加载、优化器、固定预处理和评价不会同比下降。若为了匹配32回答/步而改成16题，则单步不会自然快4倍，只是看过更多不同题。两种口径必须分清。

评价使用完整City378与外部88，列出相同题呈现量下的成绩曲线、实际总耗时、阈值翻转和几何分层。用户已要求A/B继续到550，该要求保持；此处的耗时用于测量效率，不重新设小时截断。

### 候选二：用已有GT补足学习信号，减少在线优化的回答数

我们本来就有目标框标准答案。可用少量当前策略回答进行比较，同时让GT作为单独正监督；减少参与反向的重复分支。最小实现应从独立SFT项与RL项开始，明确权重和各自分母，避免把GT混入组均值后把尚可的采样回答全部变成负优势。

[OraRL作者论文](https://arxiv.org/abs/2608.20492)与[代码](https://github.com/HVision-NKU/OraRL)已研究标注作为正样本、独立策略基线和保留正负两侧回答的选择性反向，其任务含空间定位。作者报告的选择性反向提速约1.48倍；其“短答对长思维链”大幅解码收益不能外推给本项目已采用的短框。该论文提供机制与实现参考，不证明当前27B三模态也会提高成绩。

本项目原C550（SFT）为303/378，B59为300/378、A59为295/378，说明直接标签监督是必须保留的强对照；这些检查点更新次数和题呈现量不同，不能据此裁定充分训练后的RL必然更差。

优先级：先做G2与连续几何项的最小对照；若少采样仍出现学习不稳或大量全错组，再比较GT辅助。不要把四项新机制同时加上后归因。

## 4. 其他算法检索结果

| 路线 | 可复用内容 | 对本项目的判断 |
|---|---|---|
| MSSR，稳定单回答RL | 用历史成功率基线代替组内均值，配合熵塑形 | 候选，但不是简单设G1；原GRPO的G1会零优势。论文是二元奖励、多模态数学题，当前几何/对比奖励需要重新设计基线 |
| RLOO / REINFORCE++ | 更简单的策略梯度与基线 | 只换损失名字不自动少前向；需明确组数、基线与参考项是否真的被删减 |
| Prompt Replay | 复用高信号题目，再用当前策略重新生成 | 能提升有用题比例，但改变训练分布；保留新题与场景覆盖，防止反复训练少数边界题 |
| 轨迹回放 / 多次优化同批回答 | 减少新采样次数 | 生成仅占约26%；即使采样成本摊为零，其他阶段不变时总速度上限约1.36倍。离策略概率、旧策略与过期程度还增加复杂度 |
| DAPO动态过滤 | 过滤奖励方差为0的组并补采样 | 需要先花成本生成才能判断；当前多数饱和时补齐有效组可能增加采样。不等于免费跳过79%总算力；当前beta=.01的KL项也需重新定义 |
| 改GSPO/CISPO/Dr.GRPO归一化 | 稳定性或统计估计改动 | 不直接减少长提示重复计算，不能作为大幅速度方案的主线 |
| 拒绝采样微调 / 离线偏好训练 | 一次生成多次学习，复用已知框 | 可作为新训练方法；当前已知GT，需证明比直接SFT增加的偏好样本更有用。DPO正负两条长提示仍可共享，但普通实现也会重复计算 |

[MSSR作者论文](https://arxiv.org/html/2512.18215)与[代码](https://github.com/ruiiu/MSSR)的公平比较固定每步2048答：GRPO为256题×8，MSSR为2048题×1。因此它主要报告用更少更新达到相近成绩，7B单步反而6.9分钟对6.1分钟，不能解读成单步快8倍。当前每步仅4道题，若直接改单答且仍4题，批间优势归一化的统计条件更弱；全量初始基线还要额外生成，首轮并不免费。

[Prompt Replay作者论文](https://arxiv.org/abs/2603.21177)只复用题目并重新生成回答，以避免旧轨迹的策略滞后；报告早期进展加快，但激进复用最终收敛到基线附近。它支持适度利用已知难度，不支持声称优先抽难题必然更高分。

[DAPO作者论文](https://proceedings.neurips.cc/paper_files/paper/2025/hash/a4277440d50f1f15d2cb4c14f7e0c0d2-Abstract-Conference.html)和[轨迹回放论文](https://arxiv.org/abs/2606.04560)可作为后续参考；本轮不引入额外复杂队列和缓冲系统。

## 5. 改模型和输入结构的其他大幅提速方向

**压缩语言网络中的图像词元。** 当前提示绝大部分是视觉词元；降低IR/Depth输入网格、加入轻量视觉压缩或只保留重要区域，能减少生成、参考与训练三条路径的计算。它与共享前缀不同：共享保留同样证据，压缩可能丢掉小目标与相邻实例的细节。首选可解释的非对称分辨率对照，保留RGB定位细节，再逐项验证IR/Depth较低分辨率；不要一开始训练新的大型压缩器。网格必须保持mRoPE一致，不能直接删token后忽略位置。

[TokenPacker作者工作](https://doi.org/10.1007/s11263-025-02491-7)说明学习型视觉压缩可以减少视觉token，但其模型和任务不证明我们的三模态定位无损。最新[视觉裁剪与再训练研究](https://arxiv.org/abs/2610.33688)也指出语言阶段快3.49倍并不等于端到端快3.49倍，其测试端到端首词仅1.54倍；该预印本代码尚待公开，作为方向依据，不作为可直接采用的包。

**只训练语言网络上部并缓存冻结下部。** 若冻结前K层及对应LoRA，就可缓存其输出、免去这些层每个回答的反传；这是明确改变可训练能力的模型方案。只冻结部分LoRA而仍在更早层训练其他LoRA，并不能截断中间所有反传。它可能降低多模态适配能力，需与全语言LoRA比较成绩；优先级低于保持梯度的共享前缀。

**换更小稠密模型或稀疏专家模型。** 会减少每token计算，但现有27B适配器不能原样续训到新结构。不能用“激活参数较少”直接承诺相同比例速度：NF4专家核、路由、内存和多模态准确率都影响结果。它应归入新骨干实验，不打断已批准的A/B续训。

## 6. 与硬件升级的关系

当前48GB改装4090提供了更大的容量，但不会相应增加GPU计算单元。NF4主要解决容纳模型，不等于底层全程使用4bit算术：当前bitsandbytes反向会解量化到计算dtype，再做矩阵乘。逐层激活重计算又增加前向次数，源码见[evidence/bnb_autograd.py](evidence/bnb_autograd.py)。

如果需要较快获得实用速度而不愿投入共享训练适配，另一条直接路线是在更大显存和带宽的机器上测BF16 LoRA或维持NF4增大吞吐。[H100官方规格](https://www.nvidia.com/en-us/data-center/h100/)和[H200官方规格](https://www.nvidia.com/en-us/data-center/h200/)给出不同容量；H200为141GB、4.8TB/s。约27B权重仅BF16就约54GB，因此48GB单卡不能默认容纳完整BF16训练，80GB也仍需核算激活和优化器。

硬件方案按同一组固定回答、同精度或明确区分精度，比较完整更新秒数与费用/有效题，不引用厂商稀疏峰值推算本任务倍数。多卡数据并行会分摊计算但不减少总工作量；异步生成另用一张卡最多先覆盖约26%的生成时间，不能单独消除主要训练重复。当前没有购买、租用、迁移或关停实例。
