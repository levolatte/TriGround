## 1. 为什么每步约7.4分钟

现有A续训第61—80步均值如下，来自[真实资源记录](evidence/a-resource-steps.jsonl)，不包含本轮新训练：

| 工作 | 秒/优化器更新 | 占比 |
|---|---:|---:|
| 生成32个回答 | 116.56 | 26.24% |
| 独立旧策略概率前向 | 58.51 | 13.17% |
| 冻结参考策略概率前向 | 58.48 | 13.17% |
| 训练前向、重计算与反向 | 191.29 | 43.07% |
| 其余未覆盖开销 | 约19.3 | 约4.3% |
| 合计 | **444.13** | 100% |

梯度审计约0.062秒，优化器约0.011秒；不是主瓶颈。编码另有嵌套计时，不能再加到上述总数。

每步只有4题，但每题采8答、共32答。每个回答约23词元，而共同图像/文字提示约3500词元。微批1把这段提示送入64层语言网络反复前向和反传；旧策略、参考策略又各执行一遍。视觉冻结只免去参数更新，没有自动缓存图像特征。NF4节省权重存储，并不让所有矩阵计算都变成4bit；全部64层激活重计算进一步增加前向。

实际审计已经确认FLA的分块与递归快速内核生效，不是遗漏安装FLA；卷积仍为HF原生路径。模型已有短答案词表输出优化，不存在简单删掉3500行全词表输出就解决问题的机会。证据：[运行审计](evidence/a-runtime-audit.json)、[具体调用分析](redundancy.md)。

按444秒/步估算，原定A/B各新增491步合计约121小时纯训练，评价另计；这是速度量级说明，不是实时剩余时长，不恢复任何小时截止条件。

## 2. 优先方案与真实收益边界

| 优先级 | 方案 | 能减少什么 | 现有证据与限制 |
|---|---|---|---|
| **主线1** | **同题G8可微共享长前缀** | 共享提示的投影、MLP、注意力与反向，只分别算短答案 | P3500/R23时逻辑词元28184→3684，约7.65倍子工作量比；不等于总速度。VeOmni已有GDN实现，多图/NF4/Swift需适配 |
| **主线2** | **G2小组采样，研究连续几何反馈** | 固定每步4题时32答→8答 | 有接近4倍逐答工作量削减空间；是新算法条件，必须检验收敛与最终定位成绩 |
| 配套 | 省略多余旧策略独立前向 | 当前同步单次使用场景下每步约58.5秒 | 理论约1.15倍；仍需真实旧/当前概率与梯度对照 |
| 配套 | 冻结视觉特征、参考/生成提示复用 | 同组三图只编码一次，减少无梯度提示预填充 | 精确子阶段时间尚未测，不编造百分比；不能把语言状态直接detach |
| 次选 | GT辅助与少量正负回答反向 | 用已知标准框补信号，减少在线反向分支 | OraRL有定位相关参考；需要保持策略基线独立，是新训练方法 |
| 条件方案 | 更大显存/带宽GPU，或压缩图像词元 | 减轻量化、重计算成本；减少实际输入长度 | 硬件费用/精度变化、视觉细节损失分别评估，不用厂商峰值推算本任务 |

只优化生成，即使116.56秒全部消失，其他阶段不变时总速度也只有约1.36倍。因此vLLM可以作为后续配套，不能独立承担“大幅优化训练速度”的主目标。

**共享前缀的可行性不是凭空设想。** [VeOmni官方Qwen3.5实现](https://veomni.readthedocs.io/en/latest/examples/qwen3_5.html#shared-prefix-training)同时处理全注意力K/V、GDN递归状态和卷积历史的可微复用；[PrefixFlow](https://arxiv.org/abs/2606.01143)研究跨微批共享及延迟前缀反向；[Tree Training](https://arxiv.org/abs/2511.00413)和[HARTS](https://arxiv.org/abs/2608.28158)也覆盖混合结构。外部论文倍数只证明这一类结构值得做，不直接外推到本项目。

现成VeOmni开关遇到图像会走普通路径：不同图像的占位词元相同，不能用token相同推断视觉内容相同。最小适配应从GRPO已知同题组构建共享计划，先注入一次冻结视觉特征、保留原三维位置编号，再进入可微语言分叉。不是直接开一个配置，也不是把8份长序列硬塞到显存里。

共享后的主体激活行数接近当前单答，额外状态仍需预算。当前48GB卡已有约27—30GiB的PyTorch峰值记录；只看图组有8答就断定显存乘8也不成立。详见[结构与状态边界](redundancy.md)。

## 3. CPU复算已经排除了什么、支持什么

完整原B59的1888个回答中，组内重复文本仅6个（0.318%），所以不应投资完整答案去重作为主方案。全体回答平均22.878词元，缩短长思维链类论文也不是当前重点。

| 已有236组回答的反事实 | G2子集期望 | 原G8 |
|---|---:|---:|
| 原奖励有差异的组 | 24.61 | 49 |
| 每100个回答的有差异组数 | 5.21 | 2.60 |
| IoU项取消0.5上限后的有差异组 | 227.50 | 232 |

G2少75%的回答但保留约一半“有奖励差异的组”机会，单位回答信号机会更高。原奖励一旦IoU≥0.5即饱和；取消辅助IoU项上限能让同组框质量差异重新可见。**以上不是新模型训练，也不证明新奖励一定提分。** 小差异归一化可能放大边框噪声；保留命中主项、对照错误实例和阈值翻转才能判断。

简单2→4→8扩组只省约10.62%的回答，因为多数饱和组仍采满8；不优先构造复杂自适应队列。完整方法、条件和逐题数据见[算法报告](algorithms.md)与[机器可读复算](evidence/rollout-counterfactual.json)。

## 4. 为什么上次看起来“加速没有用”

- 原基线自身重复的梯度相对差约1.48%，参数更新约7.26%，已经超过当时1%的门槛；聚合审计的相近差异不能单独证明其改变数学目标。
- 微批2和卷积组合确有原生前向差异，但基准又把候选旧/参考概率替换成基线值，额外影响策略比率。严格固定目标测试有价值，但缺少各候选使用自身目标的原生链路对照，尚不能定位全部误差来源。
- 微批2单次固定步本来也未加速；它减少调用次数，却没有减少总提示计算。卷积组合仅小幅改善确定性版本，不能担当倍数级收益。
- GC2实际是关闭半数层的检查点，因长提示激活而OOM；不是“两层合并成一段检查点”，也没有排除所有选择性保存策略。

这些事实不构成直接采用旧候选的理由。下一次应先定位输入/前向差异，并区分共同目标数值测试与原生更新测试。详细证据：[以往失败复核](prior-failures.md)。

## 5. 建议的最小实施顺序

1. **先做一个题组的完整共享原型。** 从VeOmni现有部件移植，只处理平坦G8、同组三图和固定答案；保留原模型、LoRA、NF4、奖励、参考与损失分母。需要覆盖全注意力、GDN、卷积及第一个答案词元，不先迁移整个分布式训练框架。
2. **核对真实输入、输出和梯度后测完整更新。** 输入检查包括实际像素、网格、三维位置和答案掩码。两侧均保留自身原生old/ref，另留固定共同目标对照；记录logp、LoRA梯度、峰值显存、完整更新时间。前缀梯度被detach、图像被跳过、分母被改或缺少首词元，都算未实现目标。
3. **目标是完整更新至少2倍提速，作为工程目标而非结果承诺。** 在观察到实际瓶颈后加入冻结视觉复用、去旧前向和无梯度提示共享；只改训练反向而保留生成/参考全部重复，端到端收益会受限。不把各项百分比相加。
4. **算法侧做可解释的小对照。** G8原奖励→G2原奖励→G2连续IoU辅助项，先回答少采样和奖励饱和两个问题；必要时再加GT辅助。相同题呈现量与各自完整收敛曲线都保留，用户原有A/B550继续，不设置新的小时截断。
5. **框架迁移和硬件升级放在具体障碍之后。** Unsloth可以独立试，但未证明自动解决G8训练前缀；TRL AsyncGRPO当前多模态/混合状态限制不合适；FLA已经生效不重复折腾安装。

本轮完成的是有源码与CPU证据支持的路线裁决，尚未运行共享原型或新算法GPU训练。接续执行者以[结构报告](redundancy.md)、[框架兼容性](frameworks.md)、[算法候选](algorithms.md)为依据；当前A/B运行状态仍以原云端队列和[续训安排](../2026-10-26-quant-rl/ab-to550.md)为准。
