# 架构裁决：视觉语义与三传感器空间定位联合训练

> 本文是历史独立裁决。下文“整体替换”“保留27B视觉能力”和首轮优先级，已在后续[独立反方审查](../2026-10-25-dino-retrospective/redteam.md)中撤回；当前方向以[修订总文档](README.md)为准。保留原文供比较，不以张量接口和可反传性证明能力保留。

2026-10-25。本文是独立架构裁决和实验设计，未运行新模型。已阅读当前训练脚本、两条提交推理路径、HANDOFF、对象/主动感知/传感器三份深读报告，并据本地官方赛题文本核对输入、输出与训练边界。论文和作者源码细节沿用三份报告的逐项审读证据，不把它们说成本裁决另行复现的结果。使用 experimental-design 技能组织可证伪比较。

## 裁决

**主方案应整体替换“三张图→语言模型生成四个坐标”这条预测路径：保留 27B 的 RGB 场景语义理解，用它条件化一个保持 RGB 空间结构的三传感器对象定位解码器，由连续框头出最终框，框损失同时训练语义桥、语言 LoRA 和空间定位分支。**

这不是把 27B 剥成昂贵文本编码器，也不是给随机 `<LOC>` 向量接四维 MLP，更不是让检测器替语言模型已经选好的框修边。两个信息源在**选实例和迭代定位之前**汇合：27B 提供“描述在这个场景中意味着什么”，高分辨率空间分支保留“物体边界和传感器证据在哪里”。

赞成主 Agent 的总体方向，但首轮删掉两个没有足够监督支撑的自由度：**独立自由形变 IR 配准网络、显式目标—参照物框分类头**。保留固定邻域内的可学习 IR 注意力、数值 Depth 和对象槽间的条件自注意力。这样首轮仍是完整大结构，而不是把新方案拆成漫长的 auxiliary（辅助目标）试验。

最重要的风险是：两个预训练系统之间新学的接口可能比直接沿用 27B 更差；当前小规模人工训练材料不足以同时教会对象性、语义对齐、跨传感器对应和参照物。因此必须复用已有定位预训练，并用公开 grounding（语言定位）数据接通接口。不能拿 157 张图重复采样到若干千行，声称数据规模已支撑复杂关系网络。

## 现役实现究竟限制了什么

- `scripts/train_qwen36_27b_swift.sh` 默认 `FREEZE_VIT=true`、`FREEZE_ALIGNER=true`，语言侧 `all-linear` LoRA。脚本已有视觉解冻开关，不等于当前主模型已训练空间融合。
- `tools/predict_native_submission.py:187` 将 RGB、IR 各读成 RGB 图；16 位 Depth 经 `depth_mm_to_grayscale_rgb` 转视觉灰度，之后三图进入处理器并 `generate`。`tools/predict_submission_vllm.py:143` 复用同一路图像准备，再构造三图生成请求，输出经文本解析成为 bbox。现役没有可微的框回归损失路径、对象槽或原始数值 Depth 特征。
- 高分辨率能改变小目标信息，不能仅以“同样 max_pixels”保证新旧实际可见细节一致。现役有显式上采样与像素预算配套；新定位主干若只用 224²/448²，会把结构比较变成输入信息量比较。
- HANDOFF 的旧分数和 City 开发结果只是业务参照。新主方案不能把已经反复调过的 City 重新随机切分后称独立验证，也不能拿历史同题最佳候选分数当实际模型分数。

## 主方案的确定张量流

以下尺寸是实现建议，不是已经测出的最优配置。`B` 为批大小，`d=256` 为定位宽度，`N` 沿用选定定位 checkpoint 的槽数；使用 Grounding DINO 初始化时先保留其 900 槽，不擅自减到 100 后仍称相同初始化。

```text
较低细节 RGB + Query（图在前、完整 Query 在后）
    → Qwen3.6-27B 一次前向，语言 LoRA 可训练
    → 完整 Query token 的末层 hidden Hq: B×Lq×Dq
    → LayerNorm + 线性投影 → 语义 memory Q: B×Lq×256

高分辨率 RGB → 定位预训练 backbone → 多尺度 R_s
IR 灰度      → 同源初始化 IR 支路      → 多尺度 T_s
原始 Depth   → [数值、valid、单位已知标记] → 轻量 D_s
                      ↓
RGB 网格上的局部 IR 注意力 + 同位置有效 Depth 残差
                      ↓
融合 memory F_s: B×h_s×w_s×256，保留 RGB 坐标和尺度

预训练对象 queries + 原 BERT Query token 路径
    → 对象自注意力 / F_s 可变形交叉注意力 / 原文本交叉注意力
    → 新增 Q 语义交叉注意力残差
    → 每层 (对象槽 h_i，连续框 b_i)，最终目标分数 s_i
    → argmax(s_i) 对应的 b_i → RGB 原图归一化 xyxy
```

**27B 的视觉能力保留在哪里。** Query token 位于 RGB token 之后，因果注意力允许其读整幅 RGB 和前面的语言上下文；不是取视觉 token 均值或只取最后一个 token。首版不让 27B 再读 IR/Depth：高分辨率三模态分支负责该证据，减少两条路径重复学习融合的混淆。Qwen 语义视图虽较低细节，也须足以辨认场景对象集合，不能把小目标全部抹掉后要求语义分支解决身份。保留全部 Query hidden，并允许定位槽逐词查询，避免“一句描述压成一个向量”的瓶颈。具体接口已由主 Agent 核对实际历史 Transformers v5.16.1/v5.18.0 源码：底层 `Qwen3_5Model.forward` 返回 `last_hidden_state`，可直接取 Query 的5120维状态，无需生成或执行大词表头；处理器位置与批次掩码必须保留。详见 [Qwen接入说明](qwen-interface.md)。不能用 vLLM 生成文本代替该张量。

**保住检测初始化。** 不直接拿 Qwen hidden 替换 Grounding DINO 的 BERT embedding，否则原跨模态预训练接口立即失配。保留原 BERT 路径，在 decoder 中加一个窄的 Qwen 语义残差桥，从近零贡献开始。目标选择头作用于结合两路记忆后的槽，已有框回归头逐层预测。Grounding DINO 作者仓缺少完整公开训练 criterion（损失实现），这里必须明确补匹配/目标损失，而不是声称把推理仓打开训练开关即可。MDETR 有完整损失实现，但不能把其模块/权重直接装进 DINO 称无缝复用。

**三传感器不是三个全局 token。** `R_s/T_s/D_s` 都保留二维网格。IR 在 RGB 位置附近的小窗口内取样，注意力权重可训练，先不回归任意光流；窗口尺度由训练图实际错位测量决定。Depth 有效性在进入卷积及融合前显式编码，缺失模态标志与无效像素分开。毫米来源用固定物理尺度的 `log1p(depth_mm)` 等单调表示，不逐图 min-max 抹掉绝对距离。RGBDT500 等来源单位未核实时不能标成毫米：只开放相对数值通道，关闭绝对距离通道并给单位未知标志。插值采用有效值加权，避免 0 和正常深度插成虚假的近物体。

**首轮不宣称有对象级真实距离。** 框内均值/中位数混有背景、遮挡者；box-derived mask（由框生成的矩形掩码）不是主体分割。先让 decoder 从带 valid 的空间 Depth memory 读数值。可以输出框内统计作诊断，但不把它硬编码为对象距离、更不以此产生“最近”关系真值。若以后加入主体深度汇聚，需验证前景绑定。

**无硬候选天花板，但有学习容量上限。** 初始 query 不是最终候选框文件；每层可在连续 RGB 平面修正框，训练目标框不注入推理候选。因此不像冻结 Groma proposal 选择器受固定候选召回上限。然而有限槽数、低分辨率特征和初始化 anchor 仍会漏目标；不能说连续框自动消除了召回问题。报告初始框、各 decoder 层框的 oracle@N，分清“根本没覆盖”“修框失败”“最后选错”。

## 损失和梯度必须闭合

每条只有最终 GT 框的样本，用预测槽和这一框的匹配成本确定目标槽 `i*`，计算 `5 L1(b_i*,g)+2 (1−GIoU(b_i*,g))+CE(softmax(s),i*)`，系数仅是首轮工程起点。可以对中间 decoder 层施加同类辅助框损失，避免监督只到最后一层。目标 CE 表示“此 Query 选择哪一槽”，**不表示其余槽都是背景物体**。不能用单目标标注把画面里所有未标对象训练成 no-object，再希望它们承担参照物。

保留公开 grounding/detection（定位/检测）预训练的对象和词对齐目标，只在具备相应标注的数据上计算。单框训练样本没有名词跨度/参照物框时，不凭空增加所有词—物体对齐标签。重复表达同图不同真实目标的数据可构成目标身份对比；匹配到相同真实目标的多个高 IoU 槽不能被解释为“错邻居”，应区分槽排他损失与真实实例排名。

主梯度路径为：`L_bbox/L_target → decoder → F_s → 融合层/IR/Depth/定位主干可训练部分`，以及 `decoder → 语义桥 → Hq → 27B语言LoRA`。Qwen 主权重冻结与 `no_grad` 是不同事情：LoRA 联合训练时不能把整个 Qwen 前向放进 `no_grad` 或长期缓存 hidden。短期冻结 Qwen 预热桥接层可以缓存，但最终联合阶段必须在线前向；若继续缓存，应诚实称冻结特征融合模型。

不把 `argmax` 放在训练计算框 loss 的路径上，不把生成的坐标文本经 JSON 解析后再算可微 IoU。推理 `argmax` 合理，训练由匹配和连续预测计算损失。新网络是自定义 PyTorch/HF 推理路径，不能沿用现役 vLLM `generate` 当作已支持；只复用输入清单、坐标合法性检查和提交包装。

## 哪些一起上，哪些现在删

| 首轮一起实现 | 原因 |
|---|---|
| RGB+Query 的 27B 语义 memory、窄桥、语言 LoRA | 保留现役视觉语义能力，并让最终定位目标训练语义接口 |
| RGB 空间多尺度 memory、局部 IR 对应、valid 数值 Depth | 直接改变可用感知证据，构成三传感器新结构的核心 |
| 可学习对象槽、连续框回归、唯一目标排序 | 从文本坐标生成换成可优化定位，关系在槽间与文本注意力中表达 |
| RGB 原图坐标贯穿几何变换与逆变换 | 避免 letterbox、padding、裁剪坐标成为隐蔽瓶颈 |

首轮删：自由 IR 光流、多专家路由、检测器输出后硬 top-K 截断、显式参照框/关系分类大头、额外 SAM 分割依赖、动作 RL。它们不是永远不能做，而是各自引入独立假设，当前没有证据说明必须同时存在。

尤其“目标—参照物配对头 + 真实关系监督”不能作为默认已具备条件。现有错对象对主要是目标与竞争对象，不自动等价于句中参照物。序数还需要集合上下文，不止一个 pair；把“第三个人”化为任意二元边可能损害归纳偏置。对象自注意力允许多对象交互，首轮足够承载这条假设。之后若建立训练集内真实参照框与关系标签，可在同一结构上检验显式配对头，但不为它编造伪真值。

## 训练材料与第一轮完整实验

已准备材料仅能支撑小规模域适配和诊断：辅助轮文档列出 226 对、157 张不同图，其中 RGBDT 为 79 张/79 序列，RoboRefIt 为 78 张图；重复到更长清单不会增加独立信息。RGBDT500 原始跟踪框不能直接充作英文指代数据。RGBT-GroundBench 有真实 RGB+IR 指代表达，可用于传感器 grounding 预训练；其无 Depth，不能复制灰度补成三模态。公开 MDETR/RefCOCO 类数据可用于 RGB 语义—空间桥接，但尚未下载运行的部分要记为待获取，不能写成已可训练。所有训练来源按场景/序列排除官方测试与保留评价材料。

第一轮训练**完整主模型**，采用两个优化阶段而不是等待每个模块逐项证明后才组合：先用公开 RGB/RGBT grounding 与现有合格多模态训练源预热新增接口，冻结 27B；随后在相同训练池上联合训练语言 LoRA、桥、定位 decoder、融合与模态支路。保留一定比例公开对象监督，防止单目标小数据破坏场景对象表示。轮数/采样量按实际合法清单规模确定，不预先把“600步”当成大结构合理预算。缺失传感器的样本使用显式缺失标志，不能伪造模态。

首轮只需要以下完整比较，避免穷举组合拖住主模型：

1. **现役 27B 直接框 + 等训练数据继续训练对照**：现役冻结成绩和新等数据对照都保留。否则新模型的收益可能只是额外公开数据。
2. **完整主方案**：一次完整训练后，在独立场景验证集比较最终单框 ACC；按场景统计救回与损害，同时看实例错误、边界错误、小目标和有效辅助模态分层。输入高分辨率预算与训练用数据明确记录，不能用不同图像信息量解释为单纯架构收益。
3. **主方案去 Qwen 语义桥的重训对照**：保留原 BERT/定位骨干和相同三模态分支、训练数据与步数，回答昂贵 27B 是否真正带来视觉语义收益。结构参数量不能完全相等，应报告计算差异，不强行制造虚假的“等算力”。
4. **固定同一已训主模型的干预**：IR/Depth 分别正确、缺失、错配；Qwen 使用正确 RGB、同场景错误 RGB 或仅文本。错配破坏仅说明依赖，必须结合真实正确输入优于去模态重训对照，才说明有益使用。随机换图会引入分布外异常，不单独当因果证明。

要解释融合模块收益，后续最有信息量的一次消融是**相同数值 Depth、相同支路、相同预算，局部 Query 条件融合改为同坐标直接融合并重训**。不用首轮同时跑全部窗口、全部槽数、全部模型大小。

训练开始前只做必要的实现检查：真实样本三模态几何一致；输出框能逆映射；一次框损失反传后桥、LoRA、decoder 和模态支路确有梯度；小批样本能过拟合。这些只能排除断图和坐标错误，不能证明研究有效。City400/历史94条用于开发诊断；主裁决必须来自未反复调参的场景或序列留出组，且报告实际独立场景数。

## 真正不同的竞争路线

**竞争路线一：独立三传感器专用 Grounder。** 直接执行 [sensor-architecture.md](sensor-architecture.md) 的 QTS 或完整 MDETR 风格训练路径：所有语义与空间判断在专用视觉语言网络内完成，不部署 27B。它不是主模型少一个小 loss，而是拒绝“大模型高层视觉语义必须参与”的系统假设；更短的梯度路径、更多训练吞吐和强定位归纳偏置可能胜过 27B。与主方案比较时必须共享合法训练池及高分辨率条件，分别报告固定训练步数和实际成本，不能将吞吐优势藏起来。

**竞争路线二：保留生成范式的主动双区域观察策略。** 按 [active-rl.md](active-rl.md) 做一次可学习目标/参照区域取证，以完整轨迹最终框奖励训练。它押注缺的是高细节视觉信息分配，而非定位头。它与主方案完全不同，不要第一轮把 crop policy 再接进主方案。若真正高细节观察足以大幅纠正错实例/部件，而主模型空间分支仍漏目标，这条路线可能更强。

## 最有力的反证与停止条件

1. **27B 视觉语义没有增益。** 去桥重训模型与完整主方案同等或更好；正确 RGB 与仅文本 Qwen 条件差别很小。此时 27B 是昂贵冗余，应转独立 Grounder，而不是再给它加更多 prompt。
2. **空间路径才是新瓶颈。** 最终槽 oracle 低于现役能命中的比例，且错误集中在小目标/非典型物体。先解决空间分辨率、预训练域和对象表示；配对关系头无法拯救无可用局部特征的对象。有限槽 oracle 是诊断，不是成绩。
3. **新传感器分支只学了数据来源。** 正确模态对同域验证有益，但新场景无益；单位或 valid 模式能预测来源；换掉 IR/Depth 不损失。应撤下有关机制论断，不能靠漂亮门控热图证明融合成功。
4. **监督不够。** 在小材料上训练/开发集明显上升，独立场景下降；参照注意力任意但目标损失正常下降。这不证明需要更复杂关系头，反而说明缺少可泛化的监督与初始化。
5. **额外数据解释了全部收益。** 等数据继续训练的直接框模型也涨到相同水平。可以保留工程上更优者，但不能将增益归因于新结构。

因此，本轮真正值得下注的是“保留 27B 场景语义、另建保空间的三传感器可微定位路径”，而非同时把每篇论文的模块拼进去。只要独立场景结果推翻其中一条核心依赖，就删去该依赖或转竞争路线；没有实验结果前，不预报提分幅度。
