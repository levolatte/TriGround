# 半决赛训练数据与标注指南



City是我们此前最重要的综合训练来源。考虑到半决赛可能无法继续使用City，接下来建设一套能够承担主训练任务的新数据：**3600条合格训练Query、约700张不同RGB图，另建约400题的独立开发集。** 以RGBDT500为主，其他公开训练数据补足场景和能力缺口，规模与City相当，标注内容贴近半决赛。

### City值得继承的部分

City同时具备三模态、贴近赛题的公共场景、同图多目标监督，以及足够维持主训练的规模。按原类别字段统计，人物943题、动物749题、路灯682题、汽车608题，合计80.4%；其余包括标牌、自行车、座椅、垃圾桶、船等。新标注类别以实际目标为准，例如Query已指向三轮车上的标牌时，旧字段仍可能写着三轮车。

新数据要继承这种综合性：既有普通人物、车辆和设施，也有同类竞争、部件及关系。几百道复杂题适合试标，完整主训练集还需要足够的基础题和场景覆盖。

## 3. 半决赛需要什么样的数据

半决赛包含5691条Query、1290组三模态图，每图平均4.41题、中位3题、最多14题。同一张图可能同时考人物、设施、部件和区域，适合按同图多个不同目标组织新标注。

### 表达风格与能力覆盖

以下为全量文字统计。明确序数包括first、second及2nd、4th等写法，各类可以重叠。

| 特征       | RGBDT精标98题 | 队友RGBDT919题 | City净训练3178题 | 半决赛5691题 |
| -------- | ----------:| -----------:| ------------:| --------:|
| 英文词数中位数  | 11         | 10          | 9            | 9        |
| 颜色或明暗词   | 18.4%      | 68.8%       | 68.8%        | 42.3%    |
| 左右位置词    | 23.5%      | 24.3%       | 52.9%        | 51.2%    |
| 明确序数     | 0%         | 0.2%        | 4.5%         | 20.5%    |
| 序数或极值词   | 1.0%       | 1.8%        | 14.3%        | 34.1%    |
| 近远或距离词   | 1.0%       | 0.9%        | 0.8%         | 12.0%    |
| 红外、热或温度词 | 0%         | 0%          | 0%           | 3.2%     |

半决赛的句子整体并不长，但排序、距离和目标粒度更值得补充。关键词比例用于了解表达覆盖，实际标注仍需看图判断。

City改写过程提供了一个经验：原3707题中1496题含明确序数，最终只有163题。例如“从左数第四辆自行车”变成“中间亮绿色的山地车”。新题先核实排序；关系成立就保留，关系不成立则修正候选集合或描述，让表达准确且保留需要学习的能力。

| 半决赛常见要求           | 新数据要提供的监督             |
| ----------------- | --------------------- |
| 某群对象中的第二个         | 先限定候选群体，再确定排序方向和序位    |
| 某根柱子上的凸起、装置中的一片叶片 | 参照物、所属对象与部件的对应        |
| 离相机第二近、离船最近       | 明确距离参照，分别处理相机深度与物体间距离 |
| 两只鸟、一对标牌、骑手和车     | 明确组合成员及共同范围           |
| 阴影、倒影、道路标线        | 直接标区域范围，与所属实体分开       |
| 红外中的主体或热区域        | 明确模态证据以及在RGB上的对应范围    |

### 图像与模态特点

| 图组数  | RGB和IR             | Depth              |
| ----:| ------------------ | ------------------ |
| 1193 | 1920×1080，RGB模式PNG | 16位单通道PNG          |
| 97   | 640×360，RGB模式JPEG  | 8位三通道JPEG，物理编码尚未确定 |

按文件排序间隔抽取的61组16位Depth中，全图零值比例中位24.9%，14组超过一半。距离题应检查目标主体的有效区域；文件存在不代表目标有深度证据。新数据也保留辅助模态无效、但RGB仍可回答的样本。

这些特点要求标注兼顾细部件和小目标，记录图像实际尺寸、Depth类型及来源显示规则。

## 4. 新主训练集做多大、做什么

### 数量与来源

| 项目    | 制作目标                         |
| ----- | ---------------------------- |
| 训练集   | 3600条去重后的合格Query，约700张不同RGB图 |
| 独立开发集 | 约400题、80–100图，与训练按序列或实际地点分开  |
| 试标批次  | 250–300题，合格部分计入3600题         |
| 主要来源  | RGBDT500；其他公开训练数据补场景、类别与能力缺口 |

RGBDT500本地Train包有400个序列、4000个带原生跟踪框的帧。先从通过测试重叠排除的训练素材选代表帧，再补同图其他实例和部件；有明显视角、遮挡或尺度变化时，再选同序列其他帧。约700图、3600题意味着平均每图约5题：丰富场景可做4–6题，简单场景少做，优先增加不同目标。

优先覆盖人物活动、动物群体、道路车辆、公共设施、室内物件和密集小目标。RGBDT缺少的内容由其他合适的公开训练来源补充。真实三模态承担主训练，RGBT和Robo等两模态材料用于专项补充，单列数量与比例。

本轮按City不能继续使用准备，训练和新开发集独立建设。官方测试图不进入标注池。旧RGBDT标注用于选样和参考，最终分别统计新场景、新目标或关系、旧标签纠错及复用题。

### 内容配比

按每题的主要训练目的计数，其他能力作为附加标签。

| 主要内容            | 比例   | 3600题参考量 | 300题试标参考量 |
| --------------- | ----:| --------:| ---------:|
| 基础对象、外观、动作与直接位置 | 35%  | 1260     | 105       |
| 同类竞争与排序         | 25%  | 900      | 75        |
| 参照关系及关系组合       | 15%  | 540      | 45        |
| 整物、部件、组合与区域范围   | 15%  | 540      | 45        |
| 有证据的距离、红外与弱光互补  | 10%  | 360      | 30        |
| 合计              | 100% | 3600     | 300       |

排序题同时覆盖整图排序和限定群体后的排序。范围题以整物、部件和组合为主，阴影、倒影、标线选择边界清楚的素材。距离和红外题按可靠素材产出，缺额转到实例区分、参照或范围题，记录调整后的实际比例。

### 工作分配

高致远统一训练/开发分组和领图清单。沈茜琳、周家琦按序列或场景分包制作，交换盲审，有分歧的题集中裁决。

先共同完成20图统一表达和边界，再完成250–300题试标，随后扩展至3600题。开发集在领图阶段单独划分，题型比例与主训练集一致，兼顾普通题和专项题。

每批汇总Query数、不同图数、序列/场景组数、来源与模态比例、题型分布，以及修改和拒绝原因。相邻帧和同图多题分别计数，判断新增的是场景覆盖还是同场景监督。

## 5. 一道题怎样标好

### 先确定目标与范围

在原RGB图上明确目标，标记以下一种单位：

| 目标单位 | 框的范围                          |
| ---- | ----------------------------- |
| 完整对象 | 包住对象所有可见部分，保留清楚可见的手、脚、角、翼、把手等 |
| 部件   | 仅指定部件，例如伞布不包含伞杆、底座            |
| 组合   | 包住明确列出的全部成员，例如骑手与自行车          |
| 区域   | 描述指定的可见区域，例如一段标线或一个完整可辨的倒影    |

默认采用可见范围的紧致外接矩形。遮挡处不外推看不见的轮廓；同一目标分离的可见部分取共同外接矩形；出画停在图像边界。组合框内自然包含背景或其他对象局部，不影响它作为共同外接框。

原跟踪框是参考。换成第二个实例、部件或组合时，重新画像素框。

### 写自然、唯一的英文描述

通常采用“目标＋一至两个有效限定”。英文以简短描述为主，关系复杂时增加必要条件。以下为句式示例，按实际图像使用。

| 类型   | 英文示例及中文含义                                                                  | 应框范围与必要记录            |
| ---- | -------------------------------------------------------------------------- | -------------------- |
| 基础对象 | The person in a blue jacket beside the bench. 长椅旁穿蓝夹克的人                    | 完整可见人物；长椅是参照物        |
| 局部排序 | The second bicycle from the left in the row beside the wall. 墙边那排从左数第二辆自行车 | 单辆自行车；记录该排候选和从左向右的顺序 |
| 参照关系 | The monkey sitting to the left of the red feeding bowl. 红色食盆左边坐着的猴子        | 猴子；核对食盆唯一，保存必要参照框    |
| 部件   | The canopy of the open red patio umbrella. 展开的红色遮阳伞的伞面                     | 仅伞布，不带支架和底座          |
| 组合   | The rider together with the bicycle they are riding. 骑车的人及其自行车             | 人和车共同外接框，记录两个成员      |
| 区域   | The reflection of the leftmost wooden post in the water. 最左侧木桩在水中的倒影       | 倒影本身；先确认对应木桩和倒影范围    |
| 距离   | The nearest of the three deer to the camera. 三只鹿中离相机最近的一只                  | 整只目标鹿，记录候选及主体距离依据    |

| 初稿问题                 | 修改方式                   |
| -------------------- | ---------------------- |
| “第二个人”，未说明在哪群人中、从哪边数 | 补候选集合和方向，核对全部候选        |
| Query写整把伞，框只覆盖伞面     | 按意图改成canopy（伞面），或重新标整伞 |
| 为简化句子，把已核实的序数全部换成颜色  | 保留有效序数，需要颜色消歧时再补颜色     |
| 单帧无法确认车辆正在行驶或停下      | 使用可见外观、朝向和位置描述         |
| “右脚”可能指身体侧或画面侧       | 明确视角，或改用清楚的画面位置关系      |

### 按实际尺寸保存坐标

先保存原RGB像素坐标`[x1,y1,x2,y2]`，再用图宽W、图高H计算归一化坐标：`[x1/W,y1/H,x2/W,y2/H]`。

换算示例：640×360图中的像素框`[64,36,192,180]`，归一化结果为`[0.1,0.1,0.3,0.5]`。原始像素框保留，不先量化成0–1000整数。

### 模态证据落在主体上

距离题先确认Depth来源的数值方向与显示方式，再查看目标主体几个有效小块和配准情况。RGBDT500当前尚未建立完整物理编码说明，不能直接按预览亮度写几米或近远。离相机最近与离另一个物体最近分别处理，后者不能只比较相机深度。

红外题记录实际可见的轮廓、相对显示响应或弱光帮助。亮度与温度的关系需要来源依据；未经标定不标绝对温度。8位三通道Depth保留其原类型，不能按16位毫米原值读取。

每题简记“RGB已足够”“IR有帮助”“Depth有帮助”或“证据不确定”。辅助模态无效但RGB可答时，题目可以保留并注明。

### 交叉复核

复核者先只看原图和Query，独立确定目标、范围和必要关系，再与标注者的框比较。顺序是：**目标是否相同 → 单位是否一致 → 描述是否唯一 → 边界是否完整 → 模态依据是否成立。**

目标相同但边界不一致时回图修正；候选不唯一或传感证据不足时重写或跳过。IoU达到0.5只代表比赛命中，精标仍按真实可见边界核对。AI可以辅助起草和检查，真人复核情况单独记录。

### 每题保存的内容

沿用JSONL，一行一题：

| 字段内容                   | 用途             |
| ---------------------- | -------------- |
| 来源、序列/场景组、帧、训练或开发划分    | 追溯素材、避免跨集合重复   |
| 三图路径、实际尺寸、实际模态与Depth类型 | 读取图像、换算坐标      |
| 英文Query、目标类别和单位        | 描述任务；类别按本题目标填写 |
| RGB像素框、归一化框、原参考框       | 保存标注和修订依据      |
| 必要候选、参照框或组合成员          | 关系、排序和组合题填写    |
| 证据模态、制作人、复核状态、简短修订原因   | 复核与数据筛选        |

同图已有Query或框被修正时同步处理关联记录。解释、竞争框和复核意见保存在元数据中，训练定位输入只使用原图与Query。

## 6. 怎样判断新数据能接替City

完成后先检查3600题的规模、约700图的覆盖、来源与题型比例、逐题复核情况，再训练模型检查定位效果。

新开发集按序列和实际地点与训练分开，保留基础定位、排序、关系、范围及模态证据各类题。模型比较固定起点、训练预算与输入设置，报告ACC@0.5、平均IoU、救回和退步题目，同时查看各题型表现。

按不依赖City建设的路线，主比较使用未经过City训练的公开基座；若另用历史适配器，注明其City训练经历。历史成绩用于了解已有水平，新数据的选择以新开发集的完整表现为依据。
