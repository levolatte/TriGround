## 题序与检查点

正式 `train_index.jsonl` 的查询以2026洗牌；每批优先2题来自新题游标，另最多2题从最近一次为混合组的题池均匀抽取，不足用新题补齐，同批不重复。重访重新生成；全错或全中即移出题池。保留抽签独立使用2027随机状态。

`order.jsonl`逐条保存呈现编号、ID、原始回答/词元、命中和实际分支。SFT逐条重放纠错题序，每题只学标准框。`batches.jsonl`记录实际更新数、活动题数、损失、梯度范数和完整批次秒数。

`checkpoint-N`中N是题呈现数，包含适配器、优化器、Python/NumPy/Torch/CUDA随机状态、保留随机状态、新题序列/游标与混合池。初始保存checkpoint-0，其后每400题及分段末保存。`loop_state.json`最后写入，标记完整保存。恢复只接受新流程同模式检查点；多出的未保存日志回滚至该完整边界，SFT恢复前缀需与纠错题序相同。旧C550只读取适配器权重。

## 计算路径

- Swift仅负责模型/模板和图像处理；生成使用HF原生接口，概率使用原生完整模型前向。
- 每题冻结视觉结果只计算一次，供两答生成、参考和活动训练复用；上下文退出释放缓存。
- 语言路径保持原生四轴位置与注意力输入。只保留预测回答词元所需的logits，语言层非重入梯度检查点，逐回答反向释放图。
- 共享语言前缀仍是独立优化；现役 `speed_code_20261028` 诊断不受新代码替换影响。旧集成基准入口已退出当前训练树；后续需要在新循环上重建数值与完整步收益比较。
