# D 原文根因与去围栏反事实

## 核对范围与方法

只审计第 1–8 个完整更新的 32 个 G8 组、256 条训练回答。原始奖励日志有 35 组，末尾 3 组属于未完成的第 9 步，未纳入计算。脚本逐条复现原奖励、格式和截断标记，并确认 8 步训练日志的损失和梯度范数均为零。没有调用模型、GPU、远程机器，也没有改训练代码或 GT。

每条原文及反事实文本、GT、负框、解析结果和奖励在 [raw_answer_diagnostics.jsonl](raw_answer_diagnostics.jsonl)。脚本是 [diagnose_d_raw.py](diagnose_d_raw.py)，汇总与 32 组奖励方差在 [summary.json](summary.json)。原日志保持原样。反事实操作严格限于：若 `</think>` 后的**完整**答案只有一个 Markdown `json` 围栏，则删除围栏标记，围栏内部 JSON 字节保持原样；不从思考过程提取或改写框，不修复数组、额外字段或坐标。

GT 与负框直接来自冻结云端正式数据快照 `evidence/d-rootcause-formal-diagnostic128.jsonl`。32 个训练 ID 均匹配；逐条严格核对 `id`、`source`、`group_id`、`negative_kind`、`occurrence_id`、`sampling_pool` 与奖励日志一致。其 GT、负例类别、来源和组 ID 也与同 32 个 ID 的 `warmup50-diagnostic32-g8-scored.jsonl` 一致；用正式负框重算预热诊断的 256 条奖励及最大负框 IoU，全部与保存记录相等。因此以下反事实使用正式数据的对应 GT 和负框。

## 原始失败结构

| 观察 | 数量 |
|---|---:|
| 完整更新回答 / G8 组 | 256 / 32 |
| 原奖励合法、命中、组内异奖 | 0、0、0 |
| `finish_reason=length` 且恰好 384 token、没有 `</think>` | 230 |
| `finish_reason=stop` 且有一个 `</think>`、最终答案为唯一代码围栏 | 26 |
| 已结束思考者：围栏内恰为单个 `{"bbox_2d":[...]}` 对象 | 13 |
| 已结束思考者：围栏内单元素数组 | 11 |
| 已结束思考者：对象带额外字段 | 1 |
| 已结束思考者：双元素数组 | 1 |
| 训练损失、梯度范数为零 | 各 8/8 步 |

230 条被长度上限截断时仍在思考区，不存在可以合法计分的最终回答。39 条在思考区已有至少一个四整数方框形字面量，21 条已有两个或更多；它们可能是候选或重复推导，不能当作最终输出。另有 177 条包含 `wait`、`actually`、`re-evaluate`、`re-check`、`re-read`、`double-check` 或 `refine` 一类重新考虑词；这是文本特征计数，不等于 177 条都发生无效循环。人工抽查显示有再次核对深度说明、重新选择目标和反复估坐标等情形，也有只是逐图分析、尚未走到坐标的回答。**推断：**在当前自由式推理输出与 384 token 上限的组合下，模型常来不及产生结束标记；仅由这些原文不能推断增加上限后会有多少正确完成。

## 仅去最终围栏的反事实

| 指标 | 结果 |
|---|---:|
| 仅改动的回答 | 26/256 |
| 严格解析合法框 | 13/256（已结束思考者的 13/26） |
| IoU ≥ 0.5 命中 | 13/256；合法框内 13/13 |
| 合法框平均 / 中位 IoU | 0.8164 / 0.8882 |
| 奖励方差大于零、GRPO 有非零组内优势的 G8 组 | 9/32 |
| 至少两个合法框的组 | 3/32 |
| 这些组内合法框的 IoU 有差异 / 几何奖励有差异 | 3/3 / **0/3** |
| 32 组总体方差之和 | 2.2275 |

9 个非零优势组的有效回答数分别为 1、2、1、1、1、1、3、1、2；其余 23 组仍全为 `-0.2`。这 9 组的奖励差异**全部来自合法框与非法回答之间的差别**。3 个拥有至少两个合法框的组内，各合法框的 IoU 虽不同，但都高于 0.5，命中项相同，IoU 奖励已封顶；合法框之间的几何奖励和总奖励均无差异。故 9/32 不能解读成已出现有效的定位选择信号，更不足以说明继续训练会改善选框。单组逐项奖励与方差见 `summary.json`。

这一反事实说明模型在少数已完成回答中能给出准确框，格式闸门屏蔽了本可出现的合法性奖励差异。它**不**说明去围栏能解决 230 条未结束思考，也不构成训练后成绩预估。围栏内部另 13 条仍不是当前奖励所要求的唯一单对象 JSON；不应把其中数组或额外字段随意转成答案，更不应从未结束思考中的坐标推断训练命中。

## 新 D 版本的候选单框协议（独立反事实）

这不是原 D 的评分口径，也未修改当前奖励或评价代码。候选仅处理唯一 `</think>` 后的完整 JSON：允许删除单层完整 `json` 围栏；最外层列表只有一个元素时才展开；对象除 `bbox_2d` 外只允许一个字符串 `label` 并删去该字段；坐标原值不变。重复 JSON 键、多个框、列表元素数不等于一、其他额外字段均拒绝。26 条已结束回答中，13 条只需去围栏，11 条是单元素列表且附 `label`，1 条是单对象附 `label`，另 1 条有两个框而保持拒绝；没有其他额外字段。

| 指标 | 候选协议 |
|---|---:|
| 合法框 / IoU ≥ 0.5 | 25/256 / 23/256 |
| 合法框平均 IoU | 0.8051 |
| 非零优势 G8 组 | 11/32 |
| 至少两个合法框的组 | 6/32 |
| 这些组内 IoU 有差异 / 几何奖励有差异 | 6/6 / **1/6** |
| 非零优势仅由合法与非法差异产生 | 10/11 组 |

唯一存在合法框之间几何奖励差异的是 `presentation:000016`：4 条合法回答中 3 条命中、1 条 IoU 为 0。这说明候选协议在这一小段日志中能产生**一组**定位选择信号，但未达到稳定训练信号的证据门槛。另一条合法但未命中的回答 IoU 为 0.3593。双框列表仍被拒绝，且 230 条未结束思考完全不受此协议帮助。若选择此协议启动新 D 修复版，训练奖励、评价和最终导出必须共用同一单框规范化定义，并先通过小规模生成、异奖组及非零梯度门槛；不能把候选反事实成绩记作原 D 结果。

## 可学习修复的约束

1. 先确认训练目标和输出协议：若优先追求有效学习与比赛成绩，可从已能完成短答的路径建立新的可比实验；若保留 D 的原生思考假设，则需要让模型在预算内稳定输出 `</think>` 后的唯一单对象 JSON。两种协议的结果不能混记为原 D 实验。
2. 针对原生思考路径，可把“简短推理后立即关闭思考，再输出裸 JSON”作为最小假设；需要检查模板边界与训练监督样本，再做受控的小规模生成门槛。仅扩大 384 token 上限会增加费用，但目前没有证据证明能达到足够的合法率；只宽容代码围栏最多先救回已观察到的 13 条。
3. 重启训练前先用固定少量题做生成和同一奖励函数的 G8 核验：记录 `</think>` 完成率、严格合法率、命中率、异奖组比例以及单步梯度范数。门槛未越过前不安排小时级训练或全量开发集评价。修复奖励解析时只考虑有明确协议的最终答案，不奖励思考区候选。

当前零梯度与 32/32 组同奖励一致：GRPO 的组内归一化优势没有差异。具体实现是否还有其他梯度问题需要在出现异奖组后再用真实单步验证；本次离线分析不能排除独立故障。

另据 [D 与 warmup50 权重 CPU 比较](../d-warmup-weight-comparison.json)，D 的 checkpoint-6 与共同 warmup50 适配器的 992 个张量、233,455,616 个参数逐项完全相同。这与零梯度诊断相符，说明已保存的 D 适配器没有可观察的参数更新。权重比较由主诊断流程完成，本脚本没有重复读取模型权重。

共享 warmup50 的保存审计显示 400 条已读监督输入，每条监督输出只涉及约 25–26 个 token 位置；项目记录把该阶段定义为短答案格式预热，短答案的 32 题 G8 诊断曾达到 256/256 合法。D 随后启用 `enable_thinking=true`、384 token 与严格的思考后 JSON 解析。**推断：**短答格式预热不能直接保证原生思考的结束标记和最终 JSON 习惯；本地没有那 400 条云端预热原样输入，故不声称逐条验证了其内容。
