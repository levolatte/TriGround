1. 从共同 warmup50 开始，以256思考＋64答案生成真实首批4题×G8。同一批输出用于检查和一步更新，原文、词元、动作掩码及奖励写入 `first_rollout.jsonl`。

3. 复用首批更新前输出作为256基线，仅增加一次同四题、同 warmup50、同 G8 的1024思考＋64答案对照。先筛选有效率和截断，再按命中数、全量 mIoU 排序；完全相同时选256。不用奖励差异数量评判模型优劣。
4. 所选长度仍需满足定位信号门槛。若选择1024，重新从 warmup50 验证一次真实更新。由新进程加载所选检查点，在固定12题上单答贪心推理，检查完整输出；12题分数不作为开发集增益。
5. 通过后，正式 D 重新从 warmup50 开始，使用 A/B 的原数据顺序，取前236次呈现、59次更新。探针权重不进入正式起点。前三次更新的12次呈现需通过定位信号检查；每步32答有效率至少95%、无答案截断，有实际非零优势时还要求有限非零梯度及参数变化。正常零方差组只记录。
6. 正式 D 与 D0 分别完成 City378＋外部88。D0 为共同 warmup50，两者使用同一思考长度、解码约束和格式政策，按完整 ID 与真值逐题比较救回、退步、命中、mIoU、无效和截断；严格格式分数由相同原文在 CPU 上复算。
