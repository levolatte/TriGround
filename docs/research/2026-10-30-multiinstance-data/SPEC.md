# 多实例街景定位数据集：构造规格

日期：2026-10-30　状态：规格已定，待数据源落地

## 一、为什么造这个（实测依据）

对 City378 开发集逐题归因，发现**训练与测试存在一个被量化的分布错配**：

| | 查询数 | 唯一图像 | 每图查询数 |
|---|---|---|---|
| **官方半决赛测试** | 5,691 | 1,290 | **4.41** |
| 开发集 City378 | 378 | 74 | **5.11** |
| **当前训练索引** | 4,905 | 2,477 | **1.98** |

当前训练数据里有 2,001 张图只带 1 个问题（占样本 41%），**而测试集全部是同图多实例**。

亲自看错例后，两种失败模式界限清楚：

* **硬失败（IoU<0.2）：大小对、认错那一个。** 例："The street light near the center of the bridge"，
  真值框与预测框**高度和尺寸几乎相同，只在 x 上相差 0.06**——模型找到了"桥上一盏街灯"，
  但在两盏里挑错了。
* **近失（IoU 0.3–0.5）：认对那一个、框太紧。** 例："The street light second from the right on the bridge"，
  真值宽 0.024、预测宽 0.012——只框住了灯杆的一部分。

**结论：缺的不是"更多街景图"，而是"同图多实例 + 关系式描述"的监督。**

## 二、官方查询的句式画像（5,691 条实测）

* **84.0% 以 "The" 开头，9.9% 以 "A"**
* 词数中位 9，字符数中位 47（短句）
* 高频关系词：`closest` 7.7%、`near` 6.3%、`on the left` 5.0%、`on the right` 4.8%、
  `behind` 3.2%、`left of` 2.8%、`right of` 2.6%、`in the foreground` 1.7%、
  `above` 1.5%、`next to` 1.5%、`in the background` 1.5%、`under` 1.3%、`beside` 1.4%
* 序数题确实存在：`The first person` 111 条、`The second person` 75、`The third person` 40
* 高频句首模板：`The {first|second|third} person`、`The person {wearing|in|standing|closest}`、
  `The {color} {class}`

生成器必须贴着这个分布，而不是自造一套更华丽的描述。

## 三、要覆盖的能力组合

| 能力池 | 目标 | 合成方式 |
|---|---|---|
| `disambiguate` | 同图多个同类实例里选中被描述的那个 | 取两个同类实例，用"左/右/上/下/最近/最远"互相区分 |
| `ordinal` | "第 N 个" | 取同类实例按 x 排序，用 `The {first/second/third} {class} from the {left/right}` |
| `tiny_extent` | 极小目标的完整范围（不是只框一部分） | 优先取面积 <0.3% 的实例，框用标注的精确外接框 |
| `attribute` | 颜色/服饰/姿态绑定 | 用类别名 + 颜色（从像素统计取主色）+ 动作词 |
| `layering` | 背景/前景/遮挡 | 按实例的下沿 y 与面积分档，用 `in the background` / `in the foreground` / `behind` |
| `anchor_relation` | 以地标为参照 | 用大目标（建筑、桥、车）作锚点，`near` / `in front of` / `left of` |

**每条样本只带一个目标框**，与赛题一致。

## 四、数据格式（复用现有训练索引 schema）

```json
{"id": "<source>_<image>_<idx>",
 "images": ["<相对 media_root 的路径>", ...],     // 1~3 张
 "messages": [{"role": "user", "content": "<image>\n...{query}...\nReturn only JSON ..."}],
 "solution": [x1, y1, x2, y2]}                    // 0-1 归一化
```

**必须放开一处约束**：`quant_grounding_config.read_train_index` 现在要求 `len(images) in (2, 3)`，
单模态样本会被拒。改为 `in (1, 2, 3)`，并让提示词按图片数选择 `_rgb_prompt` 或 `_trimodal_prompt`。

## 五、模态配比（重要）

**不全部换成纯可见光。** 理由：测试集是三模态，模型若从未见过红外/深度，推理时那两张图会变成纯噪声。

建议比例：

* **多实例街景（纯可见光）**：约 3,000 条 ← 提供消歧与框紧致度
* **保留现有三模态样本**：约 1,900 条 ← 维持模态处理能力
* 合计约 4,900 条，与现有 4,905 条**等量替换**

## 六、验收闸门（造完必须先过，否则不许训）

1. **查询句式分布贴官方**：`The` 开头比例、关系词占比、词数中位，三者与 5,691 条官方查询差不超过 10 个百分点。
2. **每图查询数 ≥ 3**：新数据集的多实例比例必须远高于现有的 59%。
3. **框的紧致度**：抽查 20 个框裁图目视，目标必须完整落在框内、且框内非目标占比低。
4. **几何自洽**：所有框在 [0,1] 内、x2>x1、y2>y1。
5. **媒体可读**：抽样 200 条，图像文件必须都能打开且尺寸一致。
6. **不污染测试集**：与官方测试集做逐像素比对，剔除完全相同的图像（按帧，不按文件名）。
