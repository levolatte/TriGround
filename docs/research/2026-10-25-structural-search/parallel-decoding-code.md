# 并行出框源码与论文核对：GroundAnything、LocateAnything

2026-10-25。核对对象为 GroundAnything 仓库 `e054ab329cfe3f1b88ca8cf279bcab3e2f12934e` 与论文 arXiv:2609.39600v2 中有关训练/阈值指标的 pp.8–17、25–28、31–43，Eagle/LocateAnything 仓库 `783f656d127ee498137b5ff52603ce36c292d317` 与论文 arXiv:2605.27365v2 正文和附录 pp.1–26。逐项追踪训练样本构造、注意力、损失、推理和强化学习入口；未下载权重或运行新模型。赛题以[官方 PDF](../../../../contest/基于大模型的多模态视觉理解与推理.pdf)为准：RGB、红外、Depth、英文 Query 对应一个 RGB 坐标系归一化框，主指标为 IoU≥0.5 的逐 Query ACC。现役单框 27B 与这些论文的多框检测 F1、每秒框数不能直接横比。

## 结论

1. **LocateAnything 中可用于准确率假设的证据是训练时增加框对齐块监督，推理仍走自回归。** [论文 Table 6(c), p.11](https://arxiv.org/pdf/2605.27365v2) 的 COCO-only 对照：NTP 单损失 Slow 为 50.1 mean F1；NTP+块损失 Slow 为 52.1。同一联合训练模型 Fast 49.6、Hybrid 51.6。因此“并行推理本身提准”不成立；并行主要换速度。附录 [Table 13, p.21](https://arxiv.org/pdf/2605.27365v2) 在 Qwen3-VL-4B 另有同 COCO-only 对照：原 NTP 50.8，同训练的 PBD Slow 52.2、Fast 49.6、Hybrid 52.0。两组是多目标检测 F1，不证明本赛单框 ACC 改善。
2. **所谓框坐标耦合是块内共享注意力的学习归纳偏置，不是显式合法框约束，也不是可微 IoU 损失。** LocateAnything 的四个坐标位在同一前向读取同一上下文与其他 mask 位，却不读取彼此实际采样出的坐标；各位置仍各自按词表交叉熵训练并取 token。GroundAnything 的扩散块则按固定响应长度切块，甚至不按框边界切。两者都不能仅凭“atomic box/parallel”保证同一实例、`x1<x2` 或 ACC@0.5。
3. **GroundAnything 当前启用的 RL 是因果策略 GRPO，不能视为扩散推理一致性优化。** 当前训练入口以普通自回归 rollout 和 teacher forcing 计算策略梯度；扩散 DecodeV4 只作下游评估。奖励含 IoU 评分，但它是离散输出后的标量奖励，不是坐标对 IoU 直接反传。仓库保留的 DARE 分支也叫 causal GRPO，不能据此声称目标 Qwen3.6-27B 的扩散路径获得 RL 保证。
4. **迁到现役 `qwen3_5` 不是改注意力掩码一个参数。** GroundAnything 为 Qwen3.5 分别处理 GatedDeltaNet 线性注意力的卷积/递归状态和全注意力的 Flex 块掩码，又重建多模态位置、双流损失及推理缓存；LocateAnything 已公开的自定义块注意力在其 Qwen2 路，Qwen3 路导入 HF 原生类，未给出 Qwen3.5 混合层路径。现役权重的能力保留与接口正确性均须独立验证。
5. **GroundAnything 的 RefCOCOg 高 mean F1 不等于更高 ACC@0.5。** 论文[表19 p.42、表20 p.43](https://arxiv.org/pdf/2609.39600v2) 明列：RefCOCOg val/test 的 F1@0.50，AR 为 94.11/93.75，DLM 为 92.66/92.78；RefCOCO、RefCOCOg、RefCOCO+ 家族的 F1@0.50，AR 为 95.54/92.66/92.65，DLM 为 91.52/88.00/87.73。DLM 的 RefCOCOg mean F1 却更高（91.61/91.10 对 84.37/83.56），与其 F1@0.95 的 88.63/87.15 对 AR 51.46/48.32 有关。论文多框 F1@0.50 仍不是本赛逐 Query ACC，且两公开权重有不同训练链；这些数字只阻止用 mean F1 宣告扩散更适合 ACC@0.5。

## GroundAnything：训练与解码究竟做了什么

**版本分流。** 训练入口按 `model_family` 选择 GroundAnything/plain-Qwen3 或 `Qwen3_5ForConditionalGeneration`，再分别包装成 `GAMQwen3DLM` 或 `GAMQwen35DLM`（[train_dlm.py L1393–1445](https://github.com/groundingpi/GroundAnything/blob/e054ab329cfe3f1b88ca8cf279bcab3e2f12934e/train/dlm/train_dlm.py#L1393-L1445)）。本仓库所列 `general/specialist/sft1/sft2.yaml` 使用 `groundinganything_qwen3`；当前 RL V2 也显式要求 `groundinganything_vlm` + `text_config.model_type=qwen3`（[trainer.py L122–149](https://github.com/groundingpi/GroundAnything/blob/e054ab329cfe3f1b88ca8cf279bcab3e2f12934e/train/rl/current/trainer.py#L122-L149)）。源码中确有 Qwen3.5 Direct Conversion 实现，但不要把它与 plain-Qwen3 的已列训练和 RL 配方混为同一验证链。

**双流 Direct Conversion。** `compute_response_blocks` 按响应 token 数固定切 32（可选8）位，不看 `<|box_start|>` 等几何边界（[hybrid.py L70–96](https://github.com/groundingpi/GroundAnything/blob/e054ab329cfe3f1b88ca8cf279bcab3e2f12934e/models/dlm/hybrid.py#L70-L96)）。训练为响应随机采噪，再构造两个互补 masked view；原始完整上下文在 clean stream 保留（[L585–662](https://github.com/groundingpi/GroundAnything/blob/e054ab329cfe3f1b88ca8cf279bcab3e2f12934e/models/dlm/hybrid.py#L585-L662)）。全注意力 noisy 位可双向读取同一 turn，也只能读更早的 clean turn，不能读当前 clean 真值（[L751–800](https://github.com/groundingpi/GroundAnything/blob/e054ab329cfe3f1b88ca8cf279bcab3e2f12934e/models/dlm/hybrid.py#L751-L800)）。训练总损失为 masked token CE 与 clean causal CE 的加权和，默认各 0.5（[L1401–1449](https://github.com/groundingpi/GroundAnything/blob/e054ab329cfe3f1b88ca8cf279bcab3e2f12934e/models/dlm/hybrid.py#L1401-L1449)、[L2111–2152](https://github.com/groundingpi/GroundAnything/blob/e054ab329cfe3f1b88ca8cf279bcab3e2f12934e/models/dlm/hybrid.py#L2111-L2152)）。这是一种 token 目标，没有训练时连续框的 IoU 梯度。

**Qwen3.5 混合层是实际移植障碍。** 全注意力层手动构造 noisy/clean QKV 与 FlexAttention 块掩码，clean 路维持因果注意力（[L1082–1123](https://github.com/groundingpi/GroundAnything/blob/e054ab329cfe3f1b88ca8cf279bcab3e2f12934e/models/dlm/hybrid.py#L1082-L1123)、[L1205–1241](https://github.com/groundingpi/GroundAnything/blob/e054ab329cfe3f1b88ca8cf279bcab3e2f12934e/models/dlm/hybrid.py#L1205-L1241)）；线性注意力层则对 noisy、clean 分开调用原生层，只传有效 token 掩码（[L1308–1399](https://github.com/groundingpi/GroundAnything/blob/e054ab329cfe3f1b88ca8cf279bcab3e2f12934e/models/dlm/hybrid.py#L1308-L1399)）。packed 路更明写 GatedDeltaNet 的 causal convolution、sequence id 和 recurrent reset（[L973–1057](https://github.com/groundingpi/GroundAnything/blob/e054ab329cfe3f1b88ca8cf279bcab3e2f12934e/models/dlm/hybrid.py#L973-L1057)）。推理仍保留先前文本，因为线性层有递归状态（[L1451–1504](https://github.com/groundingpi/GroundAnything/blob/e054ab329cfe3f1b88ca8cf279bcab3e2f12934e/models/dlm/hybrid.py#L1451-L1504)）。在 Qwen3.6-27B 上只扩大原 `attention_mask` 不会改变线性状态传播、缓存、mRoPE 或视觉占位的语义。

**RL 的目标与生成策略分离。** [RL README](https://github.com/groundingpi/GroundAnything/blob/e054ab329cfe3f1b88ca8cf279bcab3e2f12934e/train/rl/README.md) 明说仅 RLV2 causal JustGRPO 启用；[trainer.py L1–6](https://github.com/groundingpi/GroundAnything/blob/e054ab329cfe3f1b88ca8cf279bcab3e2f12934e/train/rl/current/trainer.py#L1-L6) 明说 rollout 与 teacher forcing 都是 causal policy，DLM wrapper 只是可训练检查点形式。实际循环调用 `CausalRollout.generate`、`causal_teacher_forcing_logprobs` 和 policy loss（[L433–488](https://github.com/groundingpi/GroundAnything/blob/e054ab329cfe3f1b88ca8cf279bcab3e2f12934e/train/rl/current/trainer.py#L433-L488)）。Grounding 的奖励配比为 RexOmni 风格 0.7 + strict IoU 0.3（[reward_adapter.py L25–51](https://github.com/groundingpi/GroundAnything/blob/e054ab329cfe3f1b88ca8cf279bcab3e2f12934e/train/rl/reward_adapter.py#L25-L51)）。即使 causal 输出经 RL 更好，扩散多步去噪策略的分布、错误坐标组合和最终单框 ACC 仍是待测，不可由 reward 名字推出一致性。[DARE causal adapter](https://github.com/groundingpi/GroundAnything/blob/e054ab329cfe3f1b88ca8cf279bcab3e2f12934e/train/rl/branches/dare/causal_model_adapter.py#L1-L90) 同样是保留的因果分支。

**论文中的两个最终权重不是同一组训练变量。** [GroundAnything 论文 A.4–A.9 pp.25–28](https://arxiv.org/pdf/2609.39600v2) 列明：AR 版做基座、坐标对齐、causal GRPO；DLM 版在坐标对齐后额外完成两阶段 AR→DLM 转换，再做 causal GRPO。两者 GRPO 奖励定义相同，但优化不同：DLM 学习率 `2e-6`、无参考 KL、训练 projector+language；AR 学习率 `5e-7`、参考 KL 0.02、只训练 language，归一化与 ZeRO 阶段亦不同。论文没有提供同一最终权重在 RefCOCOg 上仅切换 AR/DLM 的 F1@0.50 配对消融。论文 pp.14–15、31–34 的同权重 AR verifier 比较，问题是候选草稿的接受率、几何 miss 与时间；精确验证只保证**转换后模型自身 causal 分支**的最终输出，不能证明 DLM 最终框优于另训的 GroundAnything-VLM，也不能把草稿几何率算成最终 ACC。

仓库当前[RL README](https://github.com/groundingpi/GroundAnything/blob/e054ab329cfe3f1b88ca8cf279bcab3e2f12934e/train/rl/README.md)把可执行配方写为 24 设备 RLV2；论文表13 p.28 所报告的两个最终变体均为 256 GPU。此差异进一步要求把论文最终权重、公开仓库现行示例配置和可重跑的训练任务分开描述。

**阈值指标才对应方向。** 论文主表 p.11 的 RefCOCOg F1mIoU 是阈值 0.50–0.95 的汇总；附录 p.42 同时列出 F1@0.50 与 F1@0.95。DLM 在严格 0.95 上出现极大优势，可能是其训练/解码组合对紧框更有利；但本赛主门槛是 0.50，且每题只交一框，不能从该严格阈值或多框 F1 推断本赛提分。反过来，也不能从 AR 的 0.50 领先断言单独的扩散结构必伤准确率，因为最终权重的转换与 RL 配方未受控。

**规模不应隐去。** 论文 [A.5–A.7 pp.25–27](https://arxiv.org/pdf/2609.39600v2) 报告基座预训练总暴露超过 700B token；Stages 1–4 用 128 GPU，DLM conversion 两阶段各 256 GPU。仓库[专用阶段配置](https://github.com/groundingpi/GroundAnything/blob/e054ab329cfe3f1b88ca8cf279bcab3e2f12934e/configs/train/specialist.yaml)写约 3,000 万 sampled rows、预期 64 张 H800；[SFT1](https://github.com/groundingpi/GroundAnything/blob/e054ab329cfe3f1b88ca8cf279bcab3e2f12934e/configs/train/sft1.yaml)约 474 万，[SFT2](https://github.com/groundingpi/GroundAnything/blob/e054ab329cfe3f1b88ca8cf279bcab3e2f12934e/configs/train/sft2.yaml)约 30 万。这些源码配置规模和论文训练叙述分别记录，不把它们当同一运行的自动互证。其定位/生成能力不能归功于解码方式一个变量。

## LocateAnything：论文与执行源码相互校验

**论文的方法与对照。** 发布架构是 Moon-ViT + Qwen2.5 语言骨干，归一化 `[0,1000]` 坐标 token；一个箱块固定6位，另有语义、负例和结束块（[论文 pp.4–5](https://arxiv.org/pdf/2605.27365v2)）。训练将相同真值写作标准 NTP 和补充的 block MTP，两路共享图文上下文，NTP 保持因果，MTP 块内双向、跨块因果；优化 `L_ntp + L_mtp` 两个交叉熵（论文 pp.5–6）。源码确将检测响应切到 `</box>`/`</ref>`，填 `<text_mask>`、`<null>` 并复制一个完整 NTP 响应作监督（[locany_finetune_magi_stream.py L254–297](https://github.com/NVlabs/Eagle/blob/783f656d127ee498137b5ff52603ce36c292d317/Embodied/eaglevl/train/locany_finetune_magi_stream.py#L254-L297)、[L396–478](https://github.com/NVlabs/Eagle/blob/783f656d127ee498137b5ff52603ce36c292d317/Embodied/eaglevl/train/locany_finetune_magi_stream.py#L396-L478)），注意力实现符合块内互见、前缀可见（[mask_sdpa_utils.py L142–196](https://github.com/NVlabs/Eagle/blob/783f656d127ee498137b5ff52603ce36c292d317/Embodied/eaglevl/model/locany/mask_sdpa_utils.py#L142-L196)）。

**坐标并非联合数值优化。** 前向将拼接后所有 valid label 位送入**一次均值** `LigerFusedLinearCrossEntropyLoss`，没有 bbox L1、GIoU、IoU 或四坐标联合能量项；`shift_loss_weight` 虽算出却未传进最终 loss（[modeling_locateanything.py L277–314](https://github.com/NVlabs/Eagle/blob/783f656d127ee498137b5ff52603ce36c292d317/Embodied/eaglevl/model/locany/modeling_locateanything.py#L277-L314)）。论文 p.6 写 `L=L_ntp+L_mtp`，若理解为两路分别求均值再等权相加，就与此代码按全部 token 一次均值不同；两路有效 token 数不同会改变梯度权重，复现时需以实际源码为准。块内 mask 位的隐藏状态能交换上下文，但在一次前向里不知道其他位置**将会采样什么坐标**。推理 `decode_bbox_avg` 实际对四位置分别 `topk`，取第一个有效坐标 token；`hybrid` 对模糊分布做异常判断，而非计算合法四维框的联合概率（[generate_utils.py L276–361](https://github.com/NVlabs/Eagle/blob/783f656d127ee498137b5ff52603ce36c292d317/Embodied/eaglevl/utils/locany/generate_utils.py#L276-L361)）。因此“能学习几何相关”与“硬性保证边界、实例身份”必须分开。

**推理模式和论文差异。** 推理源码支持 `fast` 全并行、`slow` 逐 token、`hybrid` 并行遇异常回退；每轮重复最后一个 token 加5个 mask，执行后删掉未提交的 mask/anchor KV，再把选中 token 追加（[inference modeling L349–512](https://github.com/NVlabs/Eagle/blob/783f656d127ee498137b5ff52603ce36c292d317/Embodied/eaglevl/utils/locany/modeling_locateanything.py#L349-L512)）。论文 p.6 描述“top1<0.7 且 top5 极差>80”触发空间歧义；此 commit 的代码却使用 `<0.9` 与 `>60`（[generate_utils.py L339–355](https://github.com/NVlabs/Eagle/blob/783f656d127ee498137b5ff52603ce36c292d317/Embodied/eaglevl/utils/locany/generate_utils.py#L339-L355)）。这是真实版本差异，不应混用论文阈值复述代码。

**训练规模与评价口径。** 论文 p.14 Table 7 列四阶段 64/256/256/256 GPU、2k/20k/25k/5k 步；p.7、pp.17–20 列约 12M 唯一图、138M 以上查询、785M 框，含大量检测、多目标、UI 与合成查询，且 p.8 明说主模型另有密集目标强调阶段。官方开源[训练指南](https://github.com/NVlabs/Eagle/blob/783f656d127ee498137b5ff52603ce36c292d317/Embodied/document/TRAINING.md)是从已训 3B 权重继续 SFT 的配方，不等于零起点复现全四阶段。论文 p.11 Table 6(c) 的 COCO-only 消融较好隔离了联合块损失，仍是检测 mean F1；p.22 Table 12 的多任务 Slow 往往精度更高，例如 COCO 55.1 > Hybrid 54.7 > Fast 52.2、HumanRef 79.1 > 78.5 > 66.8。RefCOCOg val 是例外，Hybrid 73.4 > Slow 72.4。附录 Table 12 的部分数值又与正文主表不一致（如 RefCOCOg val Hybrid 73.4 与正文 Table 5 的 76.7），不能跨表拼成因果比较。论文 p.13 将 RL 明确列为未来工作。

**迁移边界。** 发布源码的 PBD 自定义注意力与 cache 逻辑集中在 Qwen2 类的 `_create_attention_mask`、Magi/SDPA/eager 分路（[modeling_qwen2.py L1119–1250](https://github.com/NVlabs/Eagle/blob/783f656d127ee498137b5ff52603ce36c292d317/Embodied/eaglevl/model/locany/modeling_qwen2.py#L1119-L1250)）；外层按配置选择此自带 Qwen2 或导入 HF `Qwen3ForCausalLM`（[modeling_locateanything.py L100–115](https://github.com/NVlabs/Eagle/blob/783f656d127ee498137b5ff52603ce36c292d317/Embodied/eaglevl/model/locany/modeling_locateanything.py#L100-L115)）。论文附录报告 Qwen3-VL-4B 上做过 COCO 对照，但仓库此处并未提供现役 Qwen3.6-27B/qwen3_5 的混合线性层、mRoPE 和多图输入适配证明；不能改掩码后直接认定可用。

## 对本项目值得检验的局部机制

**候选假设：在现役自回归单框训练中增加“框边界对齐”的辅助监督，部署仍用原自回归路径。** LocateAnything Table 6(c)/13 是理由：联合训练可提升其 Slow 路，且 Slow 保持原推理吞吐。它改变的是模型对四个坐标和同一实例的训练表征，而不是要求并行出框更快。最窄实验应从同一公开基座和清理后的合法混合建立的共享起点出发，使用完全相同的训练图组；Arm2 只作冻结历史参考，A 为等训练量直接框续训，B 为同数据/步数加框块辅助目标；两者部署都执行同一原生三图、相同分辨率及自回归唯一框。结构上只能在已经逐层核对 qwen3_5 的全注意力、线性注意力状态和位置编码后实现；也可先在较小兼容基座上做机制预实验，不能把小基座胜负直接当 27B 成绩。

**判定方式。** 按图组/场景隔离训练与评估，以最终单框 ACC@0.5 为主，记录纠正/破坏、框 IoU、无效框和错实例；对关系、部件、小目标、深度/红外有效例单列。若 B 只提高多框 F1 或边界 IoU 却不增加本赛 ACC，或把 Arm2 原正确实例改坏，就停止该机制。进一步对比“相同数据的原生 AR + 连续框损失”可区分块监督与一般额外坐标监督；连续框损失必须从真实连续框预测头或可微解码路径定义，不能把离散 token 经 argmax 再算 IoU 冒充可微训练。

上述只构成可证伪的实验方向。没有 GPU 实验结果，也没有证据支持以 GroundAnything/LocateAnything 作为新的外置裁判或直接接管现役 27B。
