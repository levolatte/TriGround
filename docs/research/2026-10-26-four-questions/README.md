# 四个问题的裁决：补数据、量化、Agent 与强化学习

2026-10-26。按用户要求，[10 月 25 日实例关系参与首次定位的结构设计](../2026-10-25-structural-search/README.md)保留为下阶段候选；不把它设成其他探索必须等待的前置条件。本轮核对本地代码、历史记录、数据包和公开一手文献，形成四份专题；没有新增标注、量化模型或 GPU 实验成绩。

## 结论与优先级

| 问题 | 当前判断 | 下一步应实际做的事 |
|---|---|---|
| 数据够不够 | 足够开展小规模比较；不足以支持“完整多实例关系能力已被覆盖”的判断。应补高质量 RGBDT500，优先独立序列和新场景 | 建 400 序列去重/覆盖表；建议先标 40 个新训练序列＋20 个新封存评估序列 |
| 27B 能否量化 | 可以，官方 FP8 已有；值得优先做同输入比较，训练省显存另考虑 QLoRA | 同源 BF16/FP8 比较单框成绩、救回/损害、峰值与吞吐；再选适配硬件的 4 位方案 |
| Agent 能否再试 | 可以，但要试训练过的主动观察与纠错策略；旧候选编号流程没有给这种机制有效结论 | 同一起点比较直接框、固定一次裁图、轨迹学习＋多轮 RL 的自适应观察 |
| RL 为什么没做 | 研究过、写过入口，没有实际跑过本项目在线 RL；长期有条件后排是执行缺口 | 短框 GRPO 独立进入下一轮，不等结构或辅助 SFT 先涨分；公开基座有有效采样即可开始 |

这些方向处在不同层面：数据提供训练证据，量化改变算力成本，Agent 改变推理时的观察动作，RL 改变学习这些动作或最终答案的方式。可以相互支持，但不能在第一组实验里全改后只报一个分数。

## 1. 高质量数据：重点补序列与判别信息

[完整数据审计与方案](data-quality.md)核对了本地完整 RGBDT500 Train.zip：400 个训练序列，每序列 10 个原生有框帧，共 4000 个跟踪目标框。论文的约 160K 训练视频帧不是 160K 条英文定位样本，原始包没有本赛所需 Query，同一轨迹的多帧也不是独立场景。

当前新增专项为 226 对、157 张图；其中 RGBDT500 只有 79 个序列上的 148 对，集中于人物和动物等内容。把同一标注重复呈现到训练清单里不能解决覆盖不足。建议补：同类竞争实例与参照关系、目标部件/完整范围/组合、确实能由 IR 或有效 Depth 消歧的题，以及实际未覆盖的室内/车辆/小物体等场景。是否存在这些题先看图确认，不按论文总类别数推断本地已标分布。

标注表达首先贴近官方/City 的自然英文唯一指代；RefCOCO/RefCOCOg 可参考实例与关系表达，PACO 可参考部件归属，但它们缺本赛真实三传感，不能替代 RGBDT500。原生跟踪框只是建议答案；如果 Query 指部件、组合或同图另一实例，就必须重新核对目标单位和框。

质量链为“有框辅助写题→只看未标图和 Query 的独立盲复核→分歧裁决与抽样人工复查”。必须允许判定无法唯一指代，不编出未能证实的热度或距离。RGBDT500 原始深度 PNG 的物理单位仍未证实，不能套用赛事官方毫米深度契约。

建议单开标注对话，另用独立上下文盲审；主对话保留路线裁决。可直接复用[标注任务说明](annotation-task.md)。本轮没有创建新对话，建议量也不是已完成量。先做小批并用新增封存场景看数据量曲线，再扩 80 个新训练序列，避免无限标数据而不问是否改善目标能力。

## 2. 量化：先试现成 FP8，不承诺本地 8GB 能装下

[量化解释、实际权重规模与实施路径](quantization.md)区分了权重、激活、生成缓存和训练额外内存。量化用较少位数近似保存数值，架构和参数个数仍是 27B。官方 BF16 张量约 55.56GB，官方 FP8 文件合计约 30.87GB；NVIDIA 的混合 NVFP4 版本由 vLLM 指南报约 22GB。运行显存还要更高，4 位的理想 13.5GB 也已超过本地 8GiB。

推理可直接评估公开 FP8 基座；若测已有任务模型，必须正确加载同一 LoRA，或先合并为 BF16 新权重再量化，不能把丢失适配器的差异算成量化损失。训练可以研究 QLoRA，即冻结低位底座、训练高精度适配器；推理 FP8 检查点不自动等同于现有训练脚本可用的 QLoRA。

先固定输入比较精度损失，再固定硬件预算比较省出的显存能否换来更高分辨率或更有效采样。FP8/4 位可能改变难例身份选择及 IoU 阈值翻转，通用基准接近不保证本赛无损；速度也必须实测，不能由位数比例推出。

## 3. Agent：训练主动看图与纠错，不复活旧控制器

[Agent 历史、论文与完整试验设计](agent-route.md)确认：旧 8B 直接框为 292/412，候选选择 273，局部细化 221，另一工具 Agent 217；这些是同一旧口径历史，不能与新 27B 官方分数直接相减。旧系统被候选池和坐标混乱卡住，最终合格教师轨迹全以选 ID 结束，正式新接口课程也没有完成训练。

DeepEyes 提供直接多轮 RL 学视觉裁图的先例；ViGoRL 提供成功/纠错轨迹热启动后再 RL 的先例；ToolsRL 说明先学习有效观察动作也可能必要。它们支持再次试验，不证明本赛涨分。建议工具从原图裁剪、RGB/IR 成对观察和可靠原深度读取开始，最终始终输出原 RGB 全图框；允许无需工具直接结束，不把 DINO 候选当答案全集。

同题比较直接框、固定一次裁图与训练后的主动多轮策略。第三臂必须包含工具返回的新像素、真实纠错轨迹与可验证终局奖励；SFT 检查点只是诊断，不要求它先赢分才进入 RL。若主动策略与固定裁图相当，就采用简单方案；若救回被破坏抵消，就停止扩大 Agent 投入。

## 4. RL：已有准备不是试过，下一轮不再有条件无限后排

[RL 时间线、代码入口与实验安排](rl-audit.md)找到 9 月路线讨论、10 月 22 日奖励论文、23 日接入设计、24 日条件计划，以及现有数据转换、奖励插件和 GRPO 脚本。没有找到真实三图采样训练日志、RL 权重或结果。因而准确回答是：**考虑过，也研究过；但没有把它推进到最小真实试验，不能说强化学习已经失败。**

下一轮先核查清洁适配器；没有现成合格起点，也可以直接从公开 Qwen3.6-27B 做 100–200 条训练 Query、每题 4 次随机生成的诊断。只要合法短框与组内奖励差异存在，就可以开展真实小步 GRPO，与同起点的普通 SFT 比较。仅输出协议不足时做有限共享热启动，不再要求先完成大规模重训或新结构胜出。

先保存未更新的采样分布，再做两步真实反向传播与重载，随后固定一段完整预算。主奖励以 ACC@0.5 过线为主、辅以不过线区间弱 IoU；奖励方差为零、无效输出和丢弃都应显式报告。直接单轮 RL 不需要先实现 Agent；多轮 Agent RL 再增加工具状态、动作和成本约束。

## 共用约束与可并行安排

旧 Arm2 训练清单有 508 行引用官方测试帧，冻结为历史工程参考；新实验使用公开基座或经训练清单审计的清洁适配器。合法训练混合、修正深度策略、图像分辨率、输出格式和评价集应在每个对照中一致。City 是已反复查看的开发集，新封存评估按序列/真实场景划分；全部 Query 计分，无效框算失败。

可以并行推进：数据侧做源序列盘点与小批补标；算力侧做 FP8 对照及单轮 GRPO。两者都无需等待完整实例关系结构或多轮 Agent 实现。Agent 另作完整机制试验，结构方案保留为并列候选。若选用量化训练，单独记录它的影响，避免把精度、数据和算法一起改变后做错误归因。

本轮完成的是研究结论及可执行实验定义，尚未获得量化、QLoRA、GRPO 或新 Agent 的本赛实测增益。
