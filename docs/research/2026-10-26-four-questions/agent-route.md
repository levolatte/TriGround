# 问题三：27B 是否值得重试多轮视觉工具 Agent？

2026-10-26。**结论：值得作为有边界的候选做一次完整机制试验；不值得把旧 8B 的候选 ID 控制器换成 27B、改提示后直接复活。** 当前证据证明旧流程对最终框严重退化，却未测试“以公开 Qwen3.6-27B 和清理后的合法任务混合建立共享起点、在原图坐标主动查看新像素、学习选择与纠错”的系统。它也未证明新系统一定胜过强直接框。保留[10 月 25 日软实例与关系结构方案](../2026-10-25-structural-search/README.md)为并列候选；两者是不同机制，按最终同题单框成绩竞争。

本轮只做代码、历史和公开一手材料审读；没有 GPU 推理或训练，没有新成绩。

## 任务和历史边界

[官方赛题 PDF](../../../../contest/基于大模型的多模态视觉理解与推理.pdf)第 2–4、6–8 页要求 RGB、红外、16 位毫米 Depth 与英文 Query 输入，输出**原 RGB 全图归一化 `xyxy` 唯一框**；主指标为全部 Query 的 ACC@0.5。Depth 0/过小无效、数值越大越远；IR 越亮越热。官方允许外部公开训练数据，但禁止赛事测试集标注或训练，以及商业闭源模型在线推理。因此测试时工具只能处理该题原始三图和模型自身推理状态，不能读取 GT、训练标签或人工改框；任何测试集 GT 仅用于离线评分。项目存档中的本地 City GT 已被反复审阅，适合开发诊断，不是独立证明。

以上复算和代码证据见[旧 DINO 复盘](../2026-10-25-dino-retrospective/README.md)、[逐题指标](../2026-10-25-dino-retrospective/metrics.md)、[代码取证](../2026-10-25-dino-retrospective/code-forensics.md)、[Agent 结果](../../../experiments/evidence_decision/RESULTS.md)与[根因审计](../../../experiments/evidence_decision/AUDIT_ROOT_CAUSES.md)。旧接口课程最后的 1064 行中 750 行只是原框复习，113 个合格教师终局全为选 ID；正式新接口 SFT 未启动，不能说“训练过的工具策略失败”。早期 2250 行学生 200 题 145、C 152，但训练图组重叠、缺同接口未训练对照，只能作诊断。[停止复盘](../../../experiments/evidence_decision/POSTMORTEM_20261001.md)明确要求旧路线收手；本提案是新的研究判断，不是授权恢复旧作业。

现役是 [Qwen3.6-27B Arm2 语言 LoRA 三图直接框](../2026-10-25-structural-search/history-and-current.md)，官方记录 0.8012；旧 City412 上同一 ck500 原生 312、二倍输入 321，详见[27B 逐题证据](../2026-10-23-reassessment/current-evidence.md)。旧工具模型是 `Qwen3-VL-8B`，现役 27B 是 `qwen3_5` 模型类型、混合线性/全注意力语言主干，且现役二倍流程先放大三图再给每图最高 8,294,400 像素；旧工具图册和局部图则受 602,112 像素预算约束。权重、可见像素、图像组织、训练任务、评测口径均不同；绝不能拿 217/412 减 0.8012 当工具的因果效应。**新机会**是较强直接定位先验和更清晰的局部原图像素；**仍缺的能力**是何时查看、如何核对实体、如何将新观察改成全图框，而参数增加不自动教会这些动作。当前 [27B 训练入口](../../../scripts/train_qwen36_27b_swift.sh)是单轮 SFT；其存在也不代表多轮图像回传、工具动作掩码和 RL 已接通。

但 Arm2 只作**冻结历史参考**。[10 月 25 日结构方案](../2026-10-25-structural-search/README.md)已核查其训练清单有 508 行引用官方测试帧；新 Agent 和结构臂都应从相同公开 Qwen3.6-27B、同一清理后的合法任务混合训练出共享直接框起点，并统一三图尺度、修正后的 Depth 渲染和输出格式。这样保留和比较直接框能力，又不继承 Arm2 训练源重叠或高值深度截白。不得把历史 0.8012 当新臂同源实验分数。

## 一手论文和源码真正提供什么

| 工作 | 已核实的机制 | 与本赛的距离 |
|---|---|---|
| [DeepEyes 论文](https://arxiv.org/html/2505.14362) §3、§4 / [官方源码](https://github.com/Visual-Agent/DeepEyes) | 基座自己给**原图区域坐标**，`zoom-in` 返回裁剪后的新图并追加到对话；整条多轮轨迹做 GRPO，奖励包括答案正确、格式和仅在正确答案时给的工具使用奖励。论文从 Qwen2.5-VL-7B/32B 的已有定位能力出发，**不靠冷启动 SFT**；训练样本挑“原视图易错而正确裁图可解”的题，报告工具调用、定位 IoU 和最终答案都有提升。源码的 `visual_toolbox_v2.py` 实现图像工具环境，训练不是把一个伪工具名写进 prompt。 | 论文主要是视觉问答和搜索，正确答案多为文本；其局部裁剪奖励与本赛唯一 RGB 框 ACC@0.5 不同。无证据证明原样策略能保住本赛已对的框；当前 27B 也尚未复现其多轮 RL。 |
| [ViGoRL 论文](https://arxiv.org/html/2505.23678) §4–5 / [官方源码](https://github.com/Gabesarch/grounded-rl) | 先用教师 MCTS 生成带坐标的**成功及纠错回退**链，SFT 让学生学会格式、视觉锚与回看；再做 GRPO。多轮版按原图点位返回高分辨率 crop，轨迹含 `<tool_call>`、`<observation>`，工具观察 token 在损失中掩码。消融：去 warm start 甚至无法产生有效格式；去空间锚或 GRPO 会降低所测任务。作者还指出固定尺寸点裁剪在 V* 上与变框裁剪接近。 | 它说明“真实纠错轨迹”比只收最终正确 ID 更有针对性，也说明不必先做复杂自由裁框。但训练数据和任务不是三传感唯一框；不能搬其成绩。 |
| [ToolsRL 论文](https://arxiv.org/html/2604.19945) §3、附录 D–F | 另一个**机制不同**的反例：先用目标区域标注奖励学准确调用 zoom，再在可自由使用工具时学最终任务，避免仅靠正确终局的稀疏奖励。其 zoom 奖励对裁图包含目标的召回宽容，和最终紧框指标分开；同时指出只奖励工具调用可产生冗余动作。 | 依赖目标级监督；本赛训练数据可用，但不能拿开发/测试 GT 生成推理时工具坐标。其旋转、画线工具不必照搬。 |

这三项支持两条训练机制：**SFT 教基本动作、原图坐标协议与真实纠错轨迹，随后在同一完整方法里用最终框奖励做多轮 RL；另设 DeepEyes 式直接多轮 RL 作动作先验充分时的对照。** 旧项目 113 个终局全为 ID，既不提供池外搜寻，也不提供自由全图改框和“看错→纠正”的轨迹，因此 SFT 要补的是明确缺失的技能。**不要求 SFT 单独超过直接框 ACC 才允许 RL**：SFT 可以只是可交互策略的热启动，最终用训练后的完整策略判断是否有效。直接 RL 则要核验基座能否自主产生合法且覆盖目标的裁图，不能把 DeepEyes “无 SFT”概括成所有模型都无需 SFT；其数据筛选、基座能力和 RL 交互环境是实质条件。

## 训练与推理接口的可行性判断

[Qwen3.6-27B 官方模型卡](https://huggingface.co/Qwen/Qwen3.6-27B)确认它是可接图像的 `qwen3_5` 架构，并给出 vLLM/SGLang 工具调用解析配置。**这仅证明推理侧能解析工具调用，不证明定位动作已学会，也不证明 RL 可直接训练。** 项目 [训练脚本](../../../scripts/train_qwen36_27b_swift.sh)已用 ms-swift 对该模型做语言 LoRA SFT。ms-swift 的[多轮 GRPO 开发文档](https://github.com/modelscope/ms-swift/blob/main/docs/source_en/Instruction/GRPO/DeveloperGuide/multi_turn.md)提供 `MultiTurnScheduler`、环境多轮回传、`rollout_infos` 动态覆盖 `images`、观察 token 损失掩码；其 [DeepEyes 示例](https://github.com/modelscope/ms-swift/blob/main/docs/source_en/Instruction/GRPO/AdvancedResearch/deepeyes.md)可作实现参考。[官方 Qwen3.5 训练实践](https://github.com/modelscope/ms-swift/blob/main/docs/source_en/BestPractices/Qwen3_8-Best-Practice.md)包含 Qwen3.5 GRPO，但示例主要是文本数学和较小/不同模型。

**可实现，不等于已核实 27B 三图多轮训练可跑。** 未发现当前项目的 `Qwen3.6-27B + 多图动态观察 + LoRA GRPO` 成功记录；DeepEyes 官方代码基于 Qwen2.5-VL。公开 [ms-swift Qwen3.5 多轮图像问题](https://github.com/modelscope/ms-swift/issues/9095)与 [视觉 RoPE 问题](https://github.com/modelscope/ms-swift/issues/9287)说明版本和逐轮图像字段要实测。先用训练源一条样本做真正两轮“出 crop→图像回传→继续出框”的前向/反向冒烟，核对模型确实消费返回像素、仅优化模型输出 token、坐标映射无误和显存。若 27B 无法在可用硬件上稳定完成，该机制暂不成立，不能用单轮文本模仿冒充训练过的视觉 Agent。RL 多 rollout 及多轮三图的显存/时延成本明显高于当前单轮 SFT；目前没有可靠数值报价。

## 提议的最小完整方法，而非旧流程换壳

决策目标是**发现全图首看漏掉的目标、核实竞争实例及范围，并最终只提交一个 RGB 全图框**。候选 ID 可作为观察线索，绝非答案全集或物体身份。共享合法 SFT 起点沿用现役原图三模态输入、Query、尺度策略和 `finish(bbox)` 直接框协议，并用同源数据训练直接框能力；它不是加载 Arm2 适配器。模型可先得到自己的首框，但训练与推理都允许不调用工具直接结束。新动作全部显式使用**原图 RGB 像素坐标/尺寸和 modality**，返回观察时附原图窗口、原图尺寸、有效像素尺度，最终框只接受原 RGB 全图归一坐标，杜绝旧“局部数字当全图数字”的文本约定。

1. `zoom(rgb, region_xyxy)`：从**原始 RGB**裁窗口再单独按高像素预算编码，提供小物体新增细节；可选点位固定视场窗口，减少自由框动作学习难度。其坐标由模型预测或训练源示范，推理不使用 GT。
2. `inspect_pair(rgb_region, ir_region)`：需要热/外观对照时保留同轮并列的 RGB、IR 裁图、来源模态及窗口；只有验证局部配准后才投影同一区域，未配准则独立看 IR 全图/区域，不把 IR 框直接当 RGB 答案。旧 `object_controller.py` 的图像预算曾删掉相关旧图，必须保证当前竞争对象的两图仍可见。
3. `depth(region_or_boxes)`：读取**原始毫米**和有效掩码，返回明确有效/无效、统计主体和相机距离；仅在 Query 的近远/遮挡关系确需距离、主体对应可靠时调用。未知值保留原因，不能把“有测量”推成“更近”，更不能以 Depth 处理左右/上下。测试图若是 JPEG 可视化深度而非毫米，绝不伪装成米数。
4. `finish(global_bbox)`：直接输出全图框；如果工具观察反驳首框，模型可明确改框，且轨迹要保留“原判断→新证据→修订”的实际过程。格式错误/工具无结果允许在固定预算内一次有反馈的恢复；不暗中替它选 GT 好框或默认保留框。

第一版**不用 DINO 搜索**：多轮价值首先应检验主动裁原图是否补到有效像素；旧 DINO 池被73个池外题卡住，且搜索基本没新增覆盖。若分析发现新 crop 有细节但仍不知往哪里找，再把 DINO 作为**额外检索工具**，按搜索区域/类别返回原图坐标候选，并与“同预算无 DINO 主动探索”配对比较；查询解析要保留完整指代与参照，不能用裸类别提示取代 Query。若训练素材无法包含实际池外目标定位，就不要声称系统解决了候选池封闭问题。

**轨迹学习的最低内容**：训练源按图组/场景独立于评价源；各臂共用合法直接框监督以抑制破坏；从真正需要看细节或对比的训练题收集可执行 `zoom/inspect_pair/depth`、真实返回图、最终全图正确框，以及有首错后的纠错轨迹。应同时含 `finish` 无工具的正确题、首框对且工具应停止的题、首框错且 crop 能改变判断的题、工具无证据应停止/换区域的题。SFT 只监督模型实际可见状态下的动作和结论，观察由工具产生并掩码；**不可把 GT 框当推理 crop 参数注入轨迹**，但训练源 GT 可监督动作位置。优先检查能否学会“保对”和“逃出池”，而不是数据总行数。随后按完整路线用最终 ACC@0.5/连续 IoU 的可验证奖励做多轮 GRPO，按工具费用惩罚冗余；SFT 的单独 ACC 只作诊断，不是 RL 的准入判据。不能靠增加工具调用率判优。

## 最小而公平的试验与停止判据

从**同一公开 Qwen3.6-27B + 清理后合法任务混合得到的共享 SFT 起点**和同一训练合法源出发，固定三图原始像素、解码/框格式、评测清单及目标总体计算上限，完成三条**完整预测器**：A 同源直接框；B 同源模型加**一次固定规则裁图**再出全图框（区分新增像素收益）；C 轨迹 SFT 热启动后用多轮 RL 训练的自适应策略（可零次、一次或多次观察）。C 的 SFT 检查点单独报告作诊断，不要求先胜 A/B；如果共享起点已能自主合法裁图，可加 D 直接多轮 RL 对照，检验 SFT 是否必要。B 的裁图规则在开发集外预定，例如以首框及上下文为中心且固定窗口倍率，不用 GT 选裁区；C/D 不可额外读取标注。若 C 用额外示范，A/B 至少共享这些训练题的最终框监督，并把工具轨迹的额外标注与 GPU 成本单独报告。每条基线都输出唯一全图框，保持同一题、同一版标签和同一推理像素/时间预算；如果 C/D 允许更多原图读取，应另报质量与成本前沿，不能把额外计算偷藏成机制收益。

先在**新冻结、按物理场景/序列隔离的留出**做一次比较；City 新版 400 仅开发诊断，改过 Query 的 27 题必须重新推理，未决标签不纳入主 GT。主要报全量 ACC@0.5、同题救回/破坏及图组配对区间；同时报原本正确题的保留率、首错且小目标/同类竞争/有效 Depth 子集的净收益、零工具/各工具调用与新增像素、最终坐标系和非法框。条件子集只解释机制，不替代全量结论。

**继续条件**是 C 在独立场景全量最终 ACC@0.5 相对 A、B 有稳定净收益，且确有“原始全图不可辨→新 crop 可辨→改成正确全图框”的可审轨迹，原本正确题的破坏不吞掉收益。若 C 与 B 相当，归因于固定新增像素即可，保留较简单方法；若 C 工具调用多、纠错少或破坏更多，停止 Agent 投入。样本少时报告真实救/损与区间和不确定性，不设任意“先赢十题”门槛。结构方案继续独立评估，不因 Agent 一轮失败而被自动证成。

## 下一位执行者接手

先核对 ms-swift 与公开 Qwen3.6-27B 的**真实多轮动态图像训练**，再从合法训练场景构建最小 `finish/zoom/纠错` 轨迹；完成 A/B/C 同预算的训练与唯一框推理。旧 `experiments/evidence_decision` 可复用原始图片工具和失败案例，但不可直接沿用匿名 P-ID 池作决策边界、低像素图册、旧 8B 控制器权重或把 1064 行课程当已训练模型。本轮为研究，未启动 GPU。
