## 设计依据及具体实现

使用本地 [Playwright 技能](F:/Tools/OpenAI/CodexHome/skills/playwright/SKILL.md)执行真实 Chromium 浏览器验证。参考 [W3C 表单教程](https://www.w3.org/WAI/tutorials/forms/)、[字段标签](https://www.w3.org/WAI/tutorials/forms/labels/)和[通知](https://www.w3.org/WAI/tutorials/forms/notifications/)，给筛选/表单建立明确标签、保存反馈和错误说明；参考 [NN/g 渐进披露](https://www.nngroup.com/articles/progressive-disclosure/)及[可用性启发式](https://www.nngroup.com/articles/ten-usability-heuristics/)，减少初始信息量，保持操作状态可见。这里借用交互原则，没有宣称通过正式可访问性认证或用户研究。

- 左侧：类别、训练/诊断、状态筛选，ID/Query 搜索、题组进度、当前筛选内下一未完成。
- 中间：完整 Query 和图像，按 RGB → 辅助 → 作者 Query/GT 揭示；同组正反题可切换，共享暴露状态。IR 全组逐题记录 RGB 判断后才可揭示 IR。
- 右侧：按当前阶段与类别展示结构化判断、备注、可选 Query 修订、批准/拒绝/待定。初始没有预填批准或 yes。批准前说明缺项；必要判断与 Query 改动使旧批准失效。
- 图像：适应窗口、100%、200%、滚动与 Esc；预览提高至最大 1920×1440 的 JPEG，不冒充原始传感器图。
- 草稿：localStorage 自动保存位置、记录与暴露状态；JSON 备份支持导入、已知题目合并和冲突确认。旧暴露状态不因导入减少；原始 Query/GT/来源不匹配拒绝导入。IR 揭示后修订 Query 不能继续复用旧盲审。
- 输出：UTF-8 BOM CSV 保留原 22 列，支持逗号、引号、多行中文；导出时重新核对已批准记录。页面不直接写项目 CSV、不自动发布数据。
- 布局：1600×1000 桌面三栏独立滚动；390×844 窄屏上下排列，无页面水平溢出。方向键换组，输入框内不会触发跳组。

## 使用边界与下一步

浏览器草稿按浏览器与 origin 隔离，file:// 与 localhost 不共享；换设备前导出 JSON，正式放行时导出 CSV 并另存 review/decisions.csv。没有多人在线同步或服务器保存；不同审核者应明确分工，合并备份时核对冲突。静态 HTML 内含答案数据，分步隐藏服务正常人审流程，不是对抗性保密机制。

实际验证仅 Chromium，未逐一验证 Safari/Firefox，也未开展真人效率测量。仍需用户与队友完成 409 条候选中的所需核准；UI 改善不证明模态互补、不改变 A/B/V 数据门槛。GPU 仍为 0，本轮训练继续等待真实人审。
