## 对第七节纠错器训练设计的必要修订

**1. KEEP 必须有可观察的 C 框，且正例应按最终动作等价处理。** 现有 412 个候选池每题均包含一个 `is_baseline=true` 的目标候选，它的框与 `c_bbox` 完全相同；该标志在选择输入中隐藏。当前选择图片调用 `annotate_candidates(image, candidates)`，没有传 `keep_box`（`results/aux_selection_refine_20260927/code_final/predict_aux_selection.py:303-354,1056-1068`），提示只写“KEEP 保留现有框”（`:407-455`）。若新模型仍不展示 C 框，就要求它判断一个未明确显示的框是否正确，会诱导按题型/难度猜 KEEP。新训练与推理都应**显式给 C 框坐标和可视标记**，并使 KEEP 与返回那个完全相同的 baseline ID 视为同一结果；若 C 已正确，其他符合真实目标的候选也不应机械罚错。

**2. “C 正确就只标 KEEP”可能让模型学到是否容易，而非是否有辅助证据。** City412 中 C 对 292 题；这些题里 131 题还存在非 baseline 的 IoU≥0.5 目标候选。其余 C 错 120 题中，47 题可由当前候选纠正，73 题没有任何正确目标候选。若将附件的“优先KEEP”实现为唯一KEEP标签，动作标签会与基线正确性、目标难度、候选来源强相关，也会把 baseline 数字 ID 这一等价正确动作当作负例。应先定义**结果等价的合法动作集合**，另外报告各动作对真实 C 框的净收益；训练中对 KEEP/换选用同场景、同难度的对照，随机化编号和排序，不输入 C 正误、对GT的IoU或GT属性。部署时可得到的检测来源、分数和C身份标记本身不是GT泄漏，可以使用，但应防范仅靠来源偏好替代对象与辅助证据判断。动作训练必须用模型在推理时看得到的字段。

**3. 没有正确候选时，选择损失不存在可用正例。** 上述 73/412 的 C 错且候选未覆盖样本，在固定框池内无动作能命中；不能硬标某个错误候选，更不能把 KEEP 当“正确答案”。可跳过它们的选择损失，另训/评估覆盖不足与证据不足的可观测置信度或 `NONE_OF_ABOVE`，并将其交回候选生成；正式提交若不得不退回 C，也要计作仍错。覆盖上限 339/412 由 292 个 C 正确加 47 个 C 错而候选可救组成。欲得 330/412（约 80%），在此固定池需兑现 330/339≈97.35% 的覆盖内命中，不能把 Oracle 上限当可达成绩。

**4. 先认对象，再选框；IoU 不是对象真值。** `city_000004_012_00000001_001` 的目标 ID 2/11 IoU 0.510，单靠这个数无法判同一人或邻接人；第 5 题目标 ID 6 与参照 ID 1 的框 IoU 0.976，同样不能把空间重合当角色相同（`city412/candidates.jsonl:1,5`）。将 RGB、IR 提议与 C 框组织成带“不确定”状态的对象簇，需要图像/掩码/人工绑定证据；对已确认的多框同对象先聚合对象分数，再在该对象内选一个 RGB 框。IoU≥0.5 可用于**最终指标的框级合格性**，但不能代替语义实例 ID。若多个不同对象的框都因重叠达到 IoU≥0.5，集合损失会优化比赛阈值，却不能证明模型学会 Query 排歧。

**5. 附件给出的多正例公式不会由普通文本 SFT 自动实现。** 若固定最多 8 个对象候选加 KEEP，可用受限动作 logits、屏蔽不存在的 ID，并对正确**对象簇**计算集合概率。多同对象框若各占一个 softmax 动作，会因复制的框越多而获得越大概率质量；需对象簇归一化，或先选对象后在簇内训练边界选择。正确且非同一对象的多个框是否都算正例，应按“竞赛 ACC 目标”与“对象推理能力”分开定义并分别报告。单 token 动作编码还需确认模型 tokenizer 中动作确为稳定单 token；否则用独立小分类头或明确定义的受限序列评分。

**6. 不能用 C 在自己训练过的 City 图像上制造代表部署分布的 KEEP 标签。** City 训练快照有 3707 Query/681 图组；412 验证题有 78 图组。精确 RGB 路径交集为零，但其中 47 题/7 图组已在地点层面列为重用，另外 365 题未获场景独立证明（`results/gu_diagnosis_20260927/cloud_snapshot/report_city412_diagnostic/summary.json` 的 `shared47_ids/other365_ids`）。第一批 City 纠错器样本若来自 C 的训练图像，其 C 预测是训练内表现，KEEP 占比和错误类型会偏乐观；应使用 C 全训练祖先未见过的场景采集，或对 C 做**地点/场景分组的交叉拟合**产生折外预测。先按物理地点及相邻序列分折，再生成同场景反向 Query、候选和所有派生样本；同一地点不得跨训练、验证、最终保留集。现有反复使用的 City412 只能作诊断集；47/365 的划分不能当独立测试认证。

**7. 对照要分清“证据对选择器的增量”与“IR 对候选覆盖的增量”。** 现有固定候选池即使标作 RGB 条件，也保留 IR 产生的候选（`predict_aux_selection.py:1004-1008`），所以固定池下 RGB vs RGB+真实辅助图/数值表只隔离**选择输入证据**，不能单独估计 IR 检测带来的候选发现。应并行报告：固定池的 RGB/真辅助/同分布空辅助三种输入，以及 RGB 单路池 vs RGB+IR 候选池的端到端覆盖和净纠正。随机移除、跨场景置换 IR/Depth 容易制造训练外输入或图像不对齐；先在训练中定义缺测/未知并保持评测格式一致，再做同题配对干预。Depth 表应保持有效性与数值分布，只在对象绑定上做受控错配；错配后的原 GT 不再是物理反事实真值，因此结果仅能说明敏感性。更强的能力检查是同一场景的“更近/更远”等相反 Query 有真实不同目标，并在对象、距离和答案三者上逐条复核。辅助证据无关或无效的题则应保持 KEEP/正确对象，不要求模型因任意置换而变差。

最小下一步不是立即扩量训练：先抽一批**实际存在竞争对象、对象 ID 与分模态证据已核准**的地点独立任务，记录 C 折外框、候选覆盖、正确对象、正确 RGB 框及无法解题状态；用相同预算比较只看 RGB 与真实辅助证据的受限动作模型，并逐图组给出纠正、破坏、KEEP、覆盖不足及 0.5 阈值附近翻转。只有真正控制最终输出的选择动作净增且对象身份核对通过，才扩大数据或复杂化模型。
