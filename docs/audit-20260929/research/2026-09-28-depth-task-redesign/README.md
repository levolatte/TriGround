# Depth 构题方向修正（2026-09-28）

## 当前实施状态

重构已完成首批14题/5场景、3类关系和CPU/浏览器验证，见[实施记录](implementation.md)。新版审核包单独保存，旧包与用户记录保留。下文是重构前的审计记录，所列构建器行号对应旧版；不代表当前仍运行全景极值算法。

## 重构前结论

用户指出的全场景极值失真、题型单一均成立。目标应改为：在可辨认对象之间利用深度层次帮助定位，包括局部比较、参考物关系、中层对象和属性与距离共同约束。继续定位RGB框，不另加辅助框输出或长解释。审计阶段只完成源码核查和候选设计；后续实现见上方实施记录。

## 已核实的代码事实

`tools/prepare_triground_abv_data.py`：

- 第152行 `_depth_core` 只统计框核心 `0 < depth < 20000` 的像素；20米及以上直接排除。这是现有代码的处理范围，不代表已证明传感器只能测20米。
- 第206–215行，只在已有同类标注且深度有效的对象中选中位数最小/最大者，再优先选深度差最大的类别。
- 第232/236行，场景按深度差从大到小挑选，进一步偏向极端比较。
- 第254行，输出却写 `nearest/farthest ... in this scene`，把局部、有缺失的排序写成全场景断言。
- 现有深度96题（64训练、32诊断）全部采用最近/最远两种句式；换类别后也仅10条不同英文，不能把同义改写计为新的推理任务。

`tools/prepare_qwen3vl_native_sft.py:37` 的模型深度可视化把19999mm以上有效数值压到灰度1，0仍是无效值。远处深度在构题统计中被剔除、在模型图中又可能饱和；提高阈值或强迫模型寻找远端极小目标不会解决构题含义问题。

## 新构题规则

1. **先选择有教学价值的对象集合，再写关系。** 目标、参考物及其主要竞争对象须在模型实际输入中可辨认。画面角落几像素的对象不作为首轮主力训练对象，但不能因为没选它，就把另一个物体称为全场景最远。
2. **比较范围写进自然语言。** 用颜色/类别/可见区域/参照物明确是哪两个或哪一组对象，不使用审核框编号、内部ID、深度有效性作为模型看不到的限定。
3. **关系改变应可能改变答案。** 限定属性用于确定竞争集合；不要先用完整独特描述把目标唯一指出，再附加一句可删除的距离描述并称为深度互补。
4. **多样性以选对象逻辑计，不按句式计。** 改写“最远→较远→远处”若仍选同样的极端对象，并没有补齐中层/相对参考关系。
5. **近处、远处是合理题型，但须语境明确。** 不统一硬设几米为“远”，不把主观距离词做成不唯一标签；优先使用自然的前景/背景分层和明确候选组。
6. **Depth证据必须落在模型能看到的图上。** 原始Z值仅作旁证，检查主体、孔洞、配准、背景混入、可视化和缩放后区分度。失效样本可用于已有可靠性题，不强凑关系标签。

## 首轮题型

以下是结构示例，不代表已经核实某幅图中的真值。

| 题型 | Query 意图 | 主要价值 |
|---|---|---|
| 限定集合的相对远近 | 这两辆白车中，离相机较远的一辆 | 避免全场景极值，比较可辨对象 |
| 明确参照物的深度关系 | 比黑色SUV离相机更远的白色轿车 | 绑定参照物，在同类目标中筛选 |
| 多层中的中间对象 | 指定三辆车中，深度位于另外两辆之间的一辆 | 不只选择深度两端，训练多对象关系 |
| 属性与层次共同定位 | 远处人群中穿红衣服的人 | RGB筛属性，Depth参与区分近/远层 |
| 有语境的近处/稍远处 | 同一区域两名相似行人中，稍远处的一人 | 覆盖非极端、适度深度差 |

前两类最容易从当前标注形成可靠候选；后几类按真实场景逐步补，不为了凑配额生成不明确题。困难样本比例按对照价值选择，不能继续只按最大深度差排序。

## 不从现有证据推导的关系

单像素Z或框核心中位数支持的是沿相机视线的深度关系，不能直接推出“离某物体的三维欧氏距离更近”。中文“在前/在后”须明确是相机视角还是物体朝向；遮挡也不是两个框Z值一比较就能自动成立。保持问题自然、简单，不在此轮引入新三维模型弥补未经核实的标签。

## 训练与评价含义

层次题即使RGB透视可解，也可以作为空间定位监督；只有加入Depth比RGB单独输入改善对象选择，才称为互补收益。对同题固定RGB、Query、生成设置，比正常/Depth置空/固定置换，记录净救回与损害；同场景正反或同属性不同层题检查是否真正随关系换对象。RGB足够题继续观察辅助模态副作用。
