# 2026-09-25 三模态数据审计与下一条提分路线

本轮范围：审计、检索、分析和路线建议。没有下载新模型或大数据、没有启动新训练，也没有重新启用 EGM/LocateAnything。M2 官方推理按此前授权独立完成，见文末。

## 1. 我的结论与需要修正的判断

**继续以三模态作为目标是合理的。目前更值得优先解决的是：训练题目是否真的教模型利用辅助信息，以及辅助信息是否以容易利用的形式进入定位过程。** 不是已经证明红外、深度没用。

“题目提供三模态”本身不能保证任一融合方法都超过 RGB：额外信息可能缺失、与当前 Query 无关，也可能被错误使用。但本轮审计找到了足够具体的数据与接口问题，值得继续做有针对性的三模态优化。RGB 仍保留作对照，用来判断新增训练真正带来什么；它不是放弃三模态的最终路线。

我此前把“先别继续加轮数”表达得过于像技术定论。实际只有两轮结果，不能排除训练不足。也不应反复把预算集中在换位置编码、门控和外围融合细节上，而忽略任务监督和数据分布。更好的 AI 可以扩大调查、减少等待和实现开销，但不能凭能力名号推断某个想法必然提分。

## 2. 当前实验究竟说明了什么

当前 M2 是 Qwen3-VL-8B-Instruct 原生三图输入、语言注意力 q/k/v/o 的 LoRA；视觉编码器和视觉特征合并模块冻结。它不是旧 C4/T4 外围融合架构。rank32、学习率1e-5、累积8，3707条×2轮共928更新，每图像素上限602112。1920×1080图实际变成1024×576，三图约1728个视觉 token。

| 方法 | 第1轮命中/412 | 第2轮命中/412 | 含义 |
|---|---:|---:|---|
| 原生 RGB R0 | 不训练 | 273 | 未做目标域微调的参照 |
| RGB LoRA R2 | 283 | 288 | 任务微调有效，尚不能断言收敛 |
| 三图 LoRA M2 | 283 | 288 | 同样训练后，新增模态没有净增 |

R2、M2 训练记录时长分别约2.10、2.46小时，均完成928更新；这不是全参数训练，不能与队友不同轮数、像素、训练模块的耗时直接比较。两者第2轮仍比第1轮增加5题，**有理由保留一次更长训练的检验，但没有理由预先保证有效**。线性调度已接近零学习率，续训需明确新调度，不能把0学习率接着跑当成延长训练。

七组 M2 干预：正常288；双错配288；双黑291；IR错配288；Depth错配287；IR黑289；Depth黑285。图组重采样区间均跨0，后三组另有换机限制。这支持“当前输出主要依赖 RGB，真实辅助信息没有形成稳定净收益”，不能区分唯一根因，更不能用双黑291宣布删除模态更好。

错误结构也很重要：M2的124个错误中，75个IoU<0.1，18个在0.1–0.3，31个在0.3–0.5。仅做边框微调不太可能解决多数错误；但低IoU也可能来自标签歧义、漏目标或选错对象，需要看图，不能一律叫推理能力不足。[本地分层统计](F:/AIC/results/rematch_20260922/next_route_error_iou_bins.json)

## 3. 训练数据的问题：已确认什么，尚不能断言什么

### 3.1 条目数不等于场景数，修了描述不等于核过框

新标签为3707训练/412验证，共759个RGB图组（681/78），12个类别。4119条记录的复核状态都写为 `query_corrected`，保留旧描述与新描述。**文件证明进行了描述修订，不能据此宣称每个框、唯一指代、三模态对应关系都做过人工复核。** 检测框可以作为定位标签起点，但一张图里有三个“黑色的人”，描述必须能唯一选出一个。

也有正常证据：按同一图像及去首尾空白、转小写后的完全相同Query分组，训练和验证均未发现“同一句话被标成多个不同框”的冲突。没有依据宣布整套标签坏了；更细的语义歧义与框边界仍需人工核查。

本轮目视的具体例子：`city_000127_009`描述是前景“小心地滑”标牌，框也对应标牌，但`class_name=person`。当前M2输入不含这个类别字段，所以这不是已证实的现有SFT错误来源；但以后按类别构建候选/同类负例时不能盲信它。同图`007/008`各把一组三个垃圾桶作为一个目标框，修订Query明确写“set of three”。因此候选系统也不能默认所有GT框都只对应一个物理实例，组合目标需要保留。一个例子证明问题存在，不代表已测出元数据错误率。

现有素材来自 city 检测数据加工是可追踪的；究竟原始官方下载包属于哪个划分，当前加工记录不足以精确复原。另一个赛道的数据也不自动低质；真正影响成绩的是场景、对象和任务是否匹配。这里不推翻团队已做的来源人工核验，也不把来源问题当停止科研的理由。

### 3.2 存在跨划分的相近场景

按文件名恢复序列时发现7组共同序列标识，涉及7张验证图、47条验证Query；现成重叠报告写0，因为文件名变体未被完整归并。7对原图均已目视确认是同一物理场景随相机移动的不同帧，非完全相同图片。

这不是“所有验证都失效”，也不是“47条都与训练有相同目标”。它说明**按图像拆分仍可能让相近场景跨训练/验证，78图组不能直接当作78个独立环境**。后续应补按采集序列/地点分开的诊断集，并保留旧412作为历史开发集，不悄悄换分母。需要先记录旧方法在新划分的表现，不能拿不同验证集的分数宣称方法提分。

反向证据也应公开：这47条R2为27/47、M2为29/47，低于其余365条的261/365、259/365。因此没有证据说这些同景题抬高了当前ACC；问题是独立场景解释不充分。

训练与复赛RGB文件名另有42个交集，对应214训练Query；验证没有同名交集。抽查`000127.png`已确认逐像素相同，其他41张本轮未逐像素确认。不能把同名全部等同于同图，也不能把214训练Query等同于214道复赛题；此事实提醒后续结果不能未经核查就称为全新图像泛化。这里不作比赛资格判断，不自动删除数据。

### 3.3 训练描述与复赛 Query 的差异比原先估计更大

下面是固定词表的词面统计，可重叠计数；不是人工语义分类，也不代表没有相关词就没有空间推理。

| 特征 | 新训练3707 | 新验证412 | 复赛测试5690 |
|---|---:|---:|---:|
| 序数表达 | 493（13.3%） | 64（15.5%） | 1387（24.4%） |
| 颜色词 | 2603（70.2%） | 285（69.2%） | 2571（45.2%） |
| 至少17词的描述 | 3 | 0 | 593（10.4%） |
| 明确 thermal/infrared/heat/temperature 词 | 0 | 0 | 164 |
| 明确 depth/meters 词 | 0 | 0 | 26 |

描述长度90分位：新训练约11词、复赛17词。训练里反复学习“颜色＋物体”，不会自动获得可靠的“从左数第三个、在某物后面、根据热信息或近远区分”。同图多条改写也不能代替新场景和真正困难的对象对。

小框也需要关注：训练537/3707、验证56/412的框面积低于整图0.1%。这不能说明所有失败是小目标，但在当前缩图下可能丢细节；有理由测试局部裁剪，而不是先把三张全图同时放大。

### 3.4 深度和红外不能仅检查“文件存在”

已有78图深度映射检查未发现整体错误或灰度全塌缩，但局部目标仍可能没有有效深度。需要区分：图像有值、目标内有值、值属于目标而非背景、与RGB真正对应，四件不同的事。

本轮已完成759图组及4119目标框的只读CPU检查：所有图组三路尺寸一致、Depth均16位，未发现整幅深度全无效；但**训练713/3707（19.2%）、验证108/412（26.2%）目标框完全没有有效深度**。框内有效比例不足10%的分别为893/3707（24.1%）、134/412（32.5%）。因此当前验证中约四分之一目标连框内距离读数都没有，不能要求深度在所有题上产生同样收益。

有效率按0<depth≤19999统计，只是初筛，不能把任意小正值都当可靠物理测量。框内中位数也不是对象真实距离，背景可能占多数；对关系题还可能使用参照物深度，不能把“目标框空洞”一律当成全题深度无用。相同尺寸也不证明像素配准准确。详细逐图、逐目标数据见[CPU检查](F:/AIC/results/city_cpu_audit_sep25.json)。

复赛输入本身有异质性：1295个引用图组中1198张16位深度PNG，97张8位可视化JPEG，涉及175条Query；其中4张全黑。JPEG没有已知毫米反变换，**不能把它们的0–255当毫米**。后续数值深度路线须明确哪些题能用真实距离，哪些只能用可靠相对信息或不能用。

详细数据证据：[训练数据深度审计](F:/AIC/docs/research/2026-09-25-training-data-deep-audit.md)。这轮检查不是逐条人工重标，尚不能给“标签错误率”或断言全部描述唯一。

RGBT-GroundBench不是今天才发现的神奇数据，旧单模态适配器阶段已经接触过其数据。新价值若成立，应来自用适合的语言/实例监督训练新入口，而不是把“重新跑旧数据”包装成新方法。

## 5. 我最看好的完整方法：让三模态分别做擅长的事

### 5.1 从“看三张图直接报坐标”改为“找对象—取证据—选对象—修边界”

设问题是“距离相机最近的、站在车旁的那个人”。可以先找到人和车，再用真实深度判断近远，结合全图确定“车旁”，最后返回那个人的框。模型不必同时从灰度图猜距离、找到所有人、理解关系、生成精确四坐标。

具体构想：

1. 保留M2全图直接答案作为候选。同时分别从RGB和IR生成目标类别的候选，取并集。**不能仅从RGB找框再读IR，否则只有IR看得见的目标一开始就被排除了。**
2. 对候选对象取掩码或保守内部区域，用原始16位深度计算有效比例、中位数和离散程度；IR提供形状、对比和弱光可见性，不把亮度当摄氏温度。
3. 模型一次看到完整场景、少量编号候选、必要RGB/IR细节和简短可靠的深度关系，例如“B明显近于A；C距离未知”。保留完整Query，输出对象编号。编号图不能代替无遮挡原图。
4. 只有边界问题明显时，再用局部图/掩码修框。不是平均不同对象的坐标。

这仍然是三模态系统，而且更直接使用了深度的物理信息。无有效深度不编数字；“左边第三个”用二维位置排序，不误用深度；“离车最近”需要对象间关系，不能用离相机最近替代；behind也可能含遮挡语义。只有候选来源、配准和关系解析都可靠，这条路线才会有效。

候选选择本身此前已经提过，不能包装成今天才想到的新点。此次收敛的实质变化是：补上独立IR候选来源，把深度从被动灰度图变成有可靠度的对象证据，并用本次发现的空洞与描述分布设计监督。既有好想法可以继续，但必须补齐此前没有验证的关键环节。

[SAM 3官方实现](https://github.com/facebookresearch/sam3)可以按短类别短语找多个对象并返回掩码/框，是候选工具之一，而不是又一个必须全面复现的主模型。其IR泛化和当前24GB显存尚未测，不保证同8B同时加载；可串行缓存。已有GroundingDINO或任务模型也可用于首个最小版本。不能用GT框喂验证推理来制造效果。

这条路线为什么比旧融合更值得试：每个失败能定位到“没找到对象、距离不可靠、关系选错、框不准”，可以用现有少量数据改进一个具体环节；不需要先做大规模全参数训练。

### 5.2 文献支持机制，但没有替我们证明分数

[DOP论文](https://arxiv.org/html/2607.11173)讨论把深度转成一句对象近远提示，比再给一张深度图更容易被模型利用，与当前问题很相关。但正文主表使用基准已有对象框、未运行检测器，不能当端到端定位提分证明。[ByDeWay](https://github.com/Rajarshi12321/ByDeWay)有深度转文本代码，但指标是问答，不是本赛BBox。

[SpatialRGPT](https://github.com/AnjieCheng/SpatialRGPT)提供对象区域与空间信息的另一种组织方式；[FineCops-Ref](https://github.com/sleepyshep/FineCops-Ref)研究复杂属性/关系与专家协作；可借监督方式和候选比较思想，不照搬指标。[RGBT-VGNet](https://github.com/crazyxiaoxi/RGBT-GroundBench)表明RGB和热红外可以区别适配，和当前全冻结视觉编码器不一样。

这里有一个反对意见必须保留：增加候选器会增加漏检和误检，候选上限不足时，再强选择器也无效。因此先测真实候选覆盖，以及“无深度/有可靠深度”是否改变正确选择。覆盖上限只用于诊断，不能报作模型成绩。

## 6. 并行保留的数据与训练路线

### 6.1 先补“必须分清哪个对象”的监督

在同一训练场景标全容易混淆的对象，补成组问题：左数第二/第三、近/远、某物左侧/右侧、弱光下热信息能区分的目标。题目不是简单改同义词，每一题必须有可核对的唯一答案。可增加少量候选编号选择、对象近远比较，再回到直接框定位，帮助M2学会利用关系。

人工标注建议从200–500个训练图组做一个可检查的起点，具体量按实际检查速度调整；不是承诺这个量能达到0.8。优先从现有错误对应类型、同类密集、明显弱光、可靠深度可分的场景取样。随机抽普通样本保留分布参照，不把全部训练变成极难题。

标注界面应同时显示RGB/IR/Depth和候选框，记录指代是否唯一、框是否正确、其他模态是否真的能提供证据、深度是否有效。描述正确但框错、框正确但描述歧义、正确却不适合训练多模态，应分开处理。先估计问题比例再批量改，不能凭猜测重写全部标签。

伪标签用于公开训练图片或已有训练池：检测/分割先给对象，几何或有效深度构造能验证的关系，模型提出描述，独立检查目标唯一性与可见性；人工优先复核来源分歧和多实例难例。不要用RGB模型凭空编“热/深”证据；不要用同一个模型生成和自评就称高质量。官方无标签测试只用于推理和输入分布观察，不纳入伪标注训练。

### 6.2 给训练量一个公平机会，但不押全部预算

数据检查后，允许一次明确的更长训练：例如固定数据的4轮R/M成对对照、保存每轮结果，必要时才延伸；和等更新的新监督/新数据方法比较。实际轮数应在下一次执行计划里确定，本报告不启动。

若清理或补任务后普通M2已经提高，先保留简单方案，不强迫使用多模块。如果更长训练仅使训练损失下降，关系/多模态子集仍无变化，再转向对象级监督。第二seed用于有实际信号的候选稳定性，不用来替每个无收益配置辩护。

### 6.3 视觉适配与新损失放在后面

当前冻结视觉编码器主要来自RGB预训练，对IR形态和深度表示不一定合适；小规模IR视觉适配或视觉LoRA值得保留，但要在正式像素下实测显存。避免一口气换基座、解冻视觉、改损失和数据而无法判断结果。

坐标文本交叉熵不直接优化IoU，几何损失/IoU奖励是合理候选；但DIST²Loss仓库尚未放出完整训练代码，大规模RL在单卡不是首选。先修监督和数据接口，再判断剩余主要是框误差还是选错对象。[DIST²Loss资源状态](https://github.com/JiwanChung/dist2loss)

### 6.4 两个额外备选：先融合图像、或明确教模型何时需要IR

图像层融合是与原生三图不同的接口方向：[Text-IF](https://github.com/XunpengYi/Text-IF)、[TarDAL](https://github.com/JinyuanLiu-CV/TarDAL)可作为研究参照。保留原RGB，再给RGB/IR融合视图，可能让RGB预训练视觉编码器更容易看到热目标；也可能改变颜色、引入伪影或因配准不准而变差。没有本题证据，适合小规模冻结接口比较，不先重训融合网络。

[DualVision](https://github.com/abrarmajeedi/DualVision)补充了明确依赖不同模态的问答监督思路及DV-204K数据线索。对我们的意义是让训练里出现“RGB不足而IR真的可用”的问题；原8GPU训练代码不直接照搬。其约25kRGB/IR图对来自LLVIP/HDRT，无Depth，问答也不等于BBox标签，不能用204k问答数量装饰本题训练规模。

## 7. 公开队伍给我们的启发，以及不能据此推断的事

没有检索到可以核实为本届AIC同赛道领先队伍的完整公开方法。你的同学成绩说明存在值得追的改进空间，但我们不知道其基座、数据、提示、官方分数口径或额外步骤，不能凭此确定一个秘密技巧。

找到的相邻赛事公开冠军[ActiveAlphaAgent/VG-SMART](https://github.com/xuetf/ICCV-2025-MARS-ActiveAlphaAgent-Solution)强调任务相近的合成数据、难例筛选、定位奖励和大模型到小模型蒸馏；公开训练配置涉及8×80GB，不能把它作为“单24GB轻量训练已获冠军”的证据。值得借的是**数据质量和错误类型驱动的训练**，不是72B或长推理本身。[官方技术说明](https://tech.meituan.com/2025/10/27/ICCV-2025.html)

## 8. 建议的下一步顺序（尚未实施）

1. **修正评估视角和标注短板**：按真实采集序列梳理划分，给多实例/空间/热红外/深度有效性补人工检查小集；保留旧412可比结果。
2. **最快的完整想法验证**：用真实RGB+IR候选和可信对象深度关系，比较M2原输出与加入对象证据后的完整412表现；同时查候选漏检。不先训练复杂排序器。
3. **数据驱动的轻训练**：一支普通M2延长训练，一支相同步数用修订后的关系/实例任务及少量RGB-T指代数据。先判断是否明显解决此前不会的题，再做稳定性复验。
4. **按瓶颈扩大**：候选漏目标就补IR候选/针对性数据；候选足但选错就训实例选择；距离误导就修配准与有效性；只差边界再上裁剪/掩码；仍缺IR表征才考虑视觉适配。

不把所有分支同时开跑；也不让“必须先完成一套巨大重构”拖住最小有信息量的实验。最终看完整准确率、错误翻转、场景分布与官方反馈，不以训练损失、候选上限或单个小子集涨分代替结果。
