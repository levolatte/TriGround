# 2026-09-25 新 City 训练数据深度审计

本审计只分析，不改训练数据、模型或提交文件，也不启动训练。目标是判断新 `3,707/412` Query 数据对复赛 Visual Grounding（视觉指代定位）是否足够贴近、标签是否可信、三模态监督是否有信息量。比赛事实以 [`contest/基于大模型的多模态视觉理解与推理.pdf`](F:/AIC/contest/基于大模型的多模态视觉理解与推理.pdf) 原文为准：输入 RGB、热红外、16 位毫米深度和英文 Query，输出 RGB 坐标系中的归一化框；主指标为 IoU≥0.5 的 Query 占比。

## 判断

这批数据是**有价值的目标域 RGB 定位训练集**：4,119 个格式有效的框、759 张不同 RGB、每张多条目标级 Query，外观、局部关系及细小目标均有覆盖。不能因其图像来源名称或部分与复赛输入同图就直接宣称数据禁用或低质。其最突出的问题是**评价独立性与模态监督目标不匹配**：训练/验证虽然按图组分开，仍有至少 7 个同一物理场景的不同帧跨划分；新 Query 更短、更强调颜色，明确的红外/深度线索近乎没有；19.2% 的训练框内深度完全无效。上述事实支持优化数据选择和独立场景复核，但不等同于“所有框错标”或“红外/深度无用”。

固定 R2 与 M2 的 412 条验证预测中，跨场景重用的 47 条反而更难：R2 27/47，对其余样本 261/365；M2 29/47，对其余 259/365。故当前数据**没有显示这一重用使总 ACC 虚高**，但它使 412 条结果不能完全解释为未见过物理场景的泛化能力。已有两轮 RGB 训练验证从 283 增至 288/412，M2 同为 288/412；这不能区分训练时长、标签信息量和模态学习机制的贡献，更不能单凭三图未涨点断定训练已饱和。

训练/验证的 ID 与 RGB 路径严格不重合；同一图内也没有发现“完全相同 Query 却对应不同框”或完全相同框重复记录。跨训练/验证有 75 种完全相同的规范化 Query 文本，但出现在不同图里，多为通用描述；它不构成图像或标签直接重复。ZIP 自带划分报告给出 seed 5843、`group_key=null`，说明是按图组随机划分，而非按物理场景或拍摄序列划分。

三模态 City 原图的 759 个 RGB 和 IR 都能打开，为 1920×1080 的 RGB 编码；759 张 Depth 均是同尺寸 `I;16` 原始 16 位 PNG，模态尺寸无不一致、没有整张深度完全无效，深度像素没有 >19999 毫米。IR 的文件编码是三通道，**不能把“三通道”误当真实彩色语义**。`ir_channel_max_delta_max=253` 来自少量角落标记；抽看的 `000127` 主体近灰度，`000433` 的 >10 通道差像素约 0.0357%，不支持“整批伪彩或 IR 无效”。

`class_name` 只有 12 种，训练中最多是 person 943、animal 749、street light 682、car 608；但这个字段不是可靠的**修订 Query 目标类别**。例如 `city_000002_082_00000121_001` 的 Query 指向红白标志牌，`class_name=tricycle`；`city_000007_004_00000433_001` 指向白衣人，`class_name=tricycle`；`city_000021_024_00000085_003` 指向白车，`class_name=tricycle`。目视 `000127.png` 中 `city_000127_009` 的湿地警示牌框 `[.19375,.755556,.327084,1]` 与图像目标吻合，而 `class_name=person` 明显不符。它保留了旧弱标签/候选类别的痕迹。此处只确认元数据与 Query 语义不一致，**不等于对应 BBox 必错**。当前 M2 直接框训练不读取 `class_name`，这个问题不会直接污染其答案损失；但用它做类别平衡、同类负例或候选生成会误判。`000127` 的另两条 Query 把三个银色垃圾桶作为一组目标并给一个框，也说明“一个框”未必总是单个物理实例；未来构造实例负例需遵循 Query 指向的对象单位。

## Query 来源及与复赛指令的距离

ZIP README 自称“Qwen 生成并通过本地规则校验”，但没有包含生成提示词、调用日志、输入模态清单或逐条人工复核记录。4,119 条均标为 `review_decision=query_corrected`，修订 Query 与 `original_query` 无完全相同。原 Query 只有 579 种不同文本，3,396/4,119 含序数/左右极值形式，和仓库 [`enrich_city_queries.py`](F:/AIC/code/tools/enrich_city_queries.py) 的框几何模板形式吻合；修订 Query 提升到 3,467 种，颜色词从原 Query 的 771 条升到 2,888 条。这支持“从几何模板改为视觉外观描述”的解释。**现有文件不能核实生成者是否实际看过 IR 或 Depth**；修订文案没有明确传感器词也不能单独证明生成时没看过。

| 词面类型（可重叠） | 训练 | 验证 | 复赛输入 |
|---|---:|---:|---:|
| 左/右 | 1,925（51.9%） | 213（51.7%） | 2,716（47.7%） |
| 序数/极值 | 493（13.3%） | 64（15.5%） | 1,387（24.4%） |
| 关系词 | 1,242（33.5%） | 122（29.6%） | 1,073（18.9%） |
| 颜色/明暗词 | 2,603（70.2%） | 285（69.2%） | 2,571（45.2%） |
| 明确 IR/热词 | 0 | 0 | 164（2.9%） |
| 明确 depth/米词 | 0 | 0 | 26（0.46%） |

这些词表只是统一的可重复近似。例如“behind”既可描述图像投影关系，也可能隐含纵深；“nearby”不一定需要毫米深度。新集外观线索很丰富，却很少让模型必须凭热辐射或测距选择对象。复赛有较长、序数和明确跨模态指令，且对象类别远超清单的 12 个旧元数据名。这是**训练目标覆盖不足的合理风险**，不能由词面统计反推模型无法在隐式场景中自发利用辅助图像。也不能把框监督说成理论上不可能学到多模态；有同类目标且额外模态能消歧时，bbox 损失仍可提供间接梯度。

复赛实际有 1,295 组三模态文件，其中 1,198 张深度为 1920×1080 `I;16` PNG，97 张为 640×360 RGB JPEG 可视化深度；后者没有毫米反变换标定，不能当 16 位距离。1,198 张 16 位复赛深度在相同有效范围定义下，整图有效比例中位 75.1%，没有整张全零。这些是**测试输入格式与质量**，不含测试标签，也不能与 City 的框内深度率直接比较。

## 原始深度的实际监督价值

| 深度指标 | City 训练 | City 验证 |
|---|---:|---:|
| 整图有效像素比例中位 | 77.0% | 79.4% |
| 整图全无效 | 0/681 | 0/78 |
| GT 框内有效比例中位 | 80.9% | 74.6% |
| GT 框内 **0** 有效像素 | 713/3,707（19.2%） | 108/412（26.2%） |
| GT 框内 <10% 有效像素 | 893/3,707（24.1%） | 134/412（32.5%） |

整图正常不代表目标区有深度。目标框中的零像素可能来自远距、反射/透射、遮挡、细杆、错位或传感器无效区；仅靠这个统计不能确定原因或证明标框错误。`000007_011_00000501_004` 是路灯细杆，既有历史诊断也显示其目标区域深度无效；对应 RGB/深度可视化里路灯可见而深度图黑区较多。对这些目标要求 Depth 辅助学习细粒度对象选择，监督信号会很弱；但仍可利用 RGB/IR 完成任务，不应直接丢弃这些框或抹黑整批数据。若以后做“深度是否帮助”的实验，至少分开报告框内深度可用/不可用子集。

7 对原图逐对目视均确认是同一物理地点、不同相机位置/帧，不是逐像素重复，也不能推断每对都含相同目标。按固定完整 412 条 R2/M2 预测重算，该 47 条的 ACC 均低于其余 365 条（数字见开头），所以不把它们称为已造成成绩抬高。云端 32×18 RGB 最近邻初筛还列出 `001229`/`001227` 等低误差跨划分候选；这些**尚未目视核实**，故 7 组只是已确认下界，不把其他候选算成场景重用。

另外，City 训练 RGB 与复赛输入 RGB 有 42 个同文件名，对应 214 条训练 Query；City 验证为 0。抽取的 `000127.png` City 与复赛两份文件经原始像素数组比较，形状均为 1080×1920×3，逐像素相等。其余 41 个只是同名候选，没有逐一比较。由这一个已验证例子可知，不能把全部复赛图称为训练未见图；但它不能证明其他同名图相同，也不能推出对整体分数的收益。**本审计不作赛道合规判断，也没有读取复赛 GT**。

## 标签目视边界与后续最小动作

已有 3 组 RGB/IR/Depth 验证可视化是由先前模态错误诊断挑出的便利样本：`000007_011_00000501` 的路灯与 30t 牌、`000011_002_00000085` 的多辆边缘车、`000019_038_00000205` 的熊与游客。它们证明部分 Query 确实需要小目标、同类区分和场景关系；也暴露边缘车的“far right / second from right”措辞值得逐条复核。但没有对全部框做人工标注重审，**不能据此给全体错标率或把自动左右几何疑点当确定错标**。格式检查为零错只能说明坐标合法，不证明 Query 与目标语义完全正确。

后续若授权做数据改进，建议按收益顺序：

1. 固定当前权重，在真正按物理场景隔离的复查子集上报告 ACC，同时保留原 412 结果作可比基线。现有 `47/365` 分层可先作诊断，不能替代新场景评估。
2. 先人工复核已观察到的类别元数据/Query 不一致、边缘及小框、模型高置信错误；给“确定错标、合理别称、只是不足以判定”分级。不要仅靠 `class_name` 或自动位置阈值批量删样本。
3. 若要提升三模态利用率，构造**有实际目标区有效深度或热差异证据**、且 RGB 难以消歧的训练/验证对照；新增与复赛更接近的长指令、序数和显式模态词。与同训练量 RGB 基线成对比较，以最终 ACC 为判断依据。保留现有 4,119 条作为强 RGB 基础，不因缺少显式模态词整体弃用。

交接：本轮没有改动训练源或图片，没有运行 GPU。复查代码/明细见上文链接；最重要的未决证据是全 4,119 条 Query↔图像↔BBox 的系统人工抽检、生成 Qwen 的实际输入/提示日志，以及 41 个同名 City/复赛 RGB 的逐像素对照。现有结论均按这些边界陈述。
