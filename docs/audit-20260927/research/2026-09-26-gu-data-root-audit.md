# G/U 新数据失效的独立数据审计（2026-09-26）

## 结论与证据等级

**已证实：数据链路没有发现 ID、图像顺序、坐标转换或深度渲染串线。** 181 条放行记录在本地和云端的 ID、对话、三张图文件名逐条一致；答案逐条等于候选框的 0–1000 坐标转换；98 张训练深度可视图逐像素等于原始 16 位图按现行公式渲染的结果，也逐像素等于人审预览。G/U 的 1600 次呈现使用同图同序，只在 183 次新数据辅助输出上改变提示与答案。重算统计见 [审计量化 JSON](2026-09-26-gu-data-root-audit-stats.json)。这排除了明显的打包错误，但云端图像内容未在本机重新下载作逐像素比对，云端读图以原有 [同步回执](../../results/gu_pilot_20260926/RESULTS.md)为证。

**已证实：这批数据主要训练“同一物体在三张图中的对应”，没有形成足量的互补推理监督。** 原 200 图组、138 条自然 Query、319 个单模态检查项中，252 项机器盲审通过；用户两份各 100 条人工结果放行 181 个输出任务，实际只有 98 条 Query、98 个目标图组。将放行 Query 与已有 [138 条逐题证据分类](../../results/existing_complement_screen_pilot/trial200_query_classification_138.jsonl)按 `bundle_id + query_id` 重连，得到 81 条 `correspondence_only`、5 条 `complement_supported` **候选**、12 条仅 RGB 可用。12 条并非 RGB 错标，而是旧分类缺乏辅助模态通过证据。5 条候选仍未证明“RGB 不足、辅助图必要”，更未证明模型使用了辅助图。实际 400 次新数据呈现中，候选只占 19 次（RGB 11、IR 8、Depth 0）；因此 **55 次 Depth 输出呈现没有一条来自该分类的互补候选**。完整复算计数见 JSON 的 `evidence_classification_*`。

**高可信推测：U 的新增监督与最终 RGB 定位目标不够一致。** G 在 183 次辅助任务位置给同题 RGB 框；U 给 IR 128 次、Depth 55 次的原模态框，而最终 412 题评估只要 RGB 框。IR/Depth 对应框与 RGB 框的归一化 IoU 中位数分别为 0.821/0.761，说明它们常是相近但不同的几何答案。U 同时改用了辅助输出提示模板，183 次都省去 G 模板的固定深度可视化说明。因此本次 G/U 差异不能单独归因于“红外/深度有无价值”或坐标切换本身；模板差异、回答坐标、框边界一起变化。G 本身也始终输入 RGB、IR、Depth 三图，**不是 RGB-only 对照**。固定 200 步 G=288/412、U=283/412，U 未表现出收益；单 seed 和同一开发集不支持更强因果结论，见 [试验结果](../../results/gu_pilot_20260926/RESULTS.md)。

## 实际使用量与独立性

| 层级 | 实际数量 | 可解释为 |
|---|---:|---|
| 原筛选池 | 200 图组、138 自然 Query、319 单模态检查项 | 制作及机器审核量，不是训练量 |
| 机器通过候选 | 252 输出任务：RGB 121、IR 92、Depth 39 | 人审前可选池 |
| 两份人工 CSV | 自然 98/100 `correct_unique`；对应 97/100 `accept` | 抽验结论，未审部分不自动批准 |
| 实际放行 | 181 输出任务：RGB 98、IR 58、Depth 25 | 98 Query、98 框定目标、98 名义 `scene_id` |
| 200 步训练 | City 1200 + 新 400，共 1600 次呈现 | 新数据占呈现 25%；每条放行任务 2 次，另 38 条第 3 次 |
| G/U 成对差异 | 183 次：IR 128、Depth 55 | G 改成同题 RGB 回答，U 保留辅助图坐标 |

City 的 1200 次呈现含 1124 个源任务、681 个图像路径；新 400 次呈现含 181 个任务、98 个图像路径。98 个 RGB 放行项恰好分属 98 个不同 `scene_id`，每个 ID 一帧；但 ID 不等于独立物理场景。直接对照原图，`rgbdt500_268_00000105` 与 `269_00000103` 是同一马拉松路段机位，`369_00000009` 与 `370_00000080` 是同一小动物铺地机位，见 [近邻对照图](2026-09-26-gu-data-root-audit-near-pairs.jpg)。只能确认至少这两对，不能由此推算总体独立场景数。未发现 98 个 RGB 路径重复；缩略图像素距离排序只是找待看图的工具，不被当作场景去重判据。

## Query、框与图像的复核

放行的 181 项源候选均为训练 split、`blind_passed`；98 个不同自然案例在人工 CSV 均为 `correct_unique`，83 个辅助输出对应案例均为 `accept`。本审计重算了这两个连接，并核对原始 Query、框及源图路径，没有发现被拒绝或待审记录混入。人工指出的 229 鹦鹉误称人已排除。人工的 `accept` 表示同物体及框范围可接受，不等于目标只能靠辅助图识别，也不等于像素级标注无误。

IR 58 个放行框相对同题 RGB 框：IoU 中位 0.821，34 个达到 0.8，1 个低于 0.5。Depth 25 个：中位 0.761，10 个达到 0.8，1 个低于 0.5。两种模态最大单坐标偏移中位分别为归一化 0.0124/0.0152。低 IoU 常发生在小目标或传感器中物体边界不同的情况；这只是**标签差异量**，不是自动判错。例：`366_00000002` 小猴 IR 框比 RGB 宽，`398_00000123` 人的 Depth 框横向偏移，原图上仍是相邻的同目标区域。视觉页：[框差异四组](2026-09-26-gu-data-root-audit-visual-1.jpg)、[另四组](2026-09-26-gu-data-root-audit-visual-2.jpg)。没有因这次审计改动任何框。

新目标整体并不比 City 更小：98 个新 RGB 目标归一化面积中位 0.02039，City 本轮 1124 个唯一源任务中位 0.006984；最短归一化边 `<0.03` 为新 5/98、City 267/1124。新数据小目标只是局部风险，不能作为整批失败根因。按本轮最大 602112 像素、原图 1920×1080 等比例缩放估算，新目标约 7/98 最短边低于 32 个输入像素，其中小猴 `366_00000002` 约 33×17 像素。这个估算没有测量模型内部实际视觉 token 尺度。

五条旧分类互补候选为 `024_00000303` 无人机、`076_00000093` 后方白动物、`271_00000039` 中间跑者、`289_00000329` 遮挡的坐者、`392_00000067` 重叠鹿，完整前缀均为 `rgbdt500_`，原始任务 ID 见 [量化 JSON](2026-09-26-gu-data-root-audit-stats.json)及 [逐题清单](../../results/existing_complement_screen_pilot/trial200_query_classification_138.jsonl)。我直接查看了这五组三模态原图及局部框（[视觉页](2026-09-26-gu-data-root-audit-visual-complement.jpg)）：IR 在无人机、跑者和鹿例中确有可见轮廓；RGB 中目标也大致可见，坐者例受前景遮挡且单图不能定量判别哪一路决定了答案。因此旧分类只用于估计**候选密度**，本次没有重新给 98 条做独立人审，也没有将五条升级为确认互补任务。其余八组抽看聚焦框差异和 Depth 可辨性；13 组视觉样本不能代表全部 98 组的错误率。

## Depth 编码与提示边界

98 组三张原图本地均存在且同为 1920×1080；RGB、IR 是 RGB 编码，原 Depth 是 16 位单通道，训练 Depth 是 RGB 灰度图。现行固定映射将原始 0 编码置黑，将正值按 1–19999 反向线性映成灰阶。**98 张原始 Depth 的像素最大值均不超过 19999，其中 86 张达到 19999；未发现 `>19999` 导致本次映射新增截断**；映射的 8 位量化仍不可逆，但没有观察到由 20000 上限造成的大面积饱和。人工审阅 `depth_visual` 与训练缓存 98/98 逐像素一致。

原始 0 编码的整图占比中位 24.18%，13/98 图超过 50%；25 个 Depth 输出框内中位 19.02%，范围约 0.09%–41.71%，详见 [深度编码统计](2026-09-26-gu-data-depth-encoding.json)和 [25 框明细](2026-09-26-gu-data-depth-validity.json)。这里的“0”只描述原始数值和**现行处理规则把它当作无效值**，未据来源确认其物理含义。框内比例包含背景，不能当成目标主体的有效率或证据充足率。视觉例 `216_00000044` 的鸟在 Depth 可视图中很暗，`111_00000142` 的坐者局部与背景难分，`398_00000123` 的人有轮廓但 Depth 与 RGB 框偏移；由于任务同时提供 RGB，不据此武断宣布 GT 错。更稳妥的结论是：这些样本可以考查跨图对应，却不足以证明 Depth 对最终 RGB 目标选择提供了额外信息。

City 原任务提示说明“亮的有效 Depth 像素较近”，新 RGB 输出提示只说明 RGBDT 原始传感器值采用固定反向映射、物理距离单位未知；这是正确避免跨来源误解的边界。U 的 183 条辅助输出提示只列三图顺序和输出坐标，**没有**这条固定映射说明，而 G 的对应 183 条有。是否影响 U 需要只改提示的对照才能判断；当前不能把它直接认定为 5 题差额的根因。

## 诊断排序与下一步

1. **数据与任务设计不匹配，证据最强。** 名义 25% 新数据仅 98 Query；400 次新呈现中 356 次来自旧分类“仅对应”、25 次来自仅 RGB 可用、19 次来自未确认互补候选；Depth 互补候选 0 次。若目标是提升最终 RGB Grounding（目标定位）中的实例/关系推理，这批任务给到的直接监督太少。
2. **U 改了输出坐标和提示，两项作用混杂。** 183 次辅助坐标答案与同题 RGB 框通常接近但不相等，且提示省略深度说明。对 IR/Depth 对应能力可能有训练价值，但目前没有把它转化为 RGB 验证收益的证据。
3. **局部图像与边界难例确实存在。** 小目标、遮挡、弱 Depth 轮廓及低 IoU 的辅助框均有目视例；新目标整体比 City 大，故不能把“小目标”或“20000 截断”说成整批系统根因。

未验证：模型是否实际读取 IR/Depth、哪类样本驱动了 G/U 差异、辅助框标注的总体误差率、RGBDT 与 City 的物理场景重叠率、换独立 seed 或外部集是否仍有同方向差异。已有固定 200 步门槛失败，本审计只用 CPU，不启动训练、改标签或再做人审。若以后重新立项，应把 **RGB 输出保持不变** 与 **真正有竞争对象/辅助独有线索的任务** 分开检验，并设计同提示模板的对照；在此之前不把对应框数量当作互补监督数量。
