# 下一阶段优先路线：数据与任务监督驱动的三模态M2

用户进一步询问收益最大的算法、训练与数据路线，并认可RGBDT500补Query。此文件收敛建议，不启动新训练。

## 决策

主预算投向“现有Qwen3-VL-8B三模态入口＋新场景数据＋对象关系/实例监督”。优先改训练内容，先保持语言LoRA、像素与直接框输出，避免同时换基座和搭复杂流水线。对象级可靠深度提示作为小规模推理试验，若有端到端收益再升级为正式选择系统。这个排序是预期收益与实施成本的判断，并非已经验证的新分数。

## 数据优先级

1. RGBDT500为首要新增真三模态图源。官方有500序列、203.7k同步三图和框，>=66类、>100场景；没有Query。官方训练划分先抽取约2000–4000个差异明显的帧图组，初版补约5000–10000条描述，按真实可用序列与标注质量调整，不保证这个规模就最优。
2. RGBT-GroundBench提供现成RGB/IR指代训练，复用已有文件优先；它不是新发现，新的用途是原生语言定位与关系训练。缺深度时使用真实两图输入，不填假深度。
3. City3707保留目标域基础，针对已确认的元数据、指代与困难对象做修订；412历史开发集保持可比，另建序列隔离复查。不得因新描述缺少模态词整体弃用。
4. RoboRefIt等RGB-D关系数据少量补充；PST900/MM5、DualVision等按缺口进入候选池，先下载样例和所需训练子集，不因可下载就全部混训。

建议首版采样起点：city40%、RGBDT500补标35%、RGB-T指代15%、RGB-D关系10%。这只是控制域差与数据源淹没的可调整起点，没有声称最优；若RGB-D实际转换暂不可用，先不强行凑比例。采样以场景/序列和任务类型为单位，不让一段视频几十个相似帧支配训练。

## RGBDT500补Query的关键约束来自任务本身

- 跟踪框提供指定目标位置，不应默认标全每帧所有竞争对象。“最近的人”“左边第三辆车”需要先找全相关参照对象并核验，不能仅看目标框生成。
- 类别/外观、二维关系、可靠深度关系、热红外可见性分别造题。不是每个目标强行写四种；不能在距离无效时编近远，在热图无区分时编温度。
- 单帧定位只保留当前三路确实可辨认的目标；不要把依赖前后帧才能知道位置的完全遮挡跟踪框直接转成静态题。
- 自动生成者可以看标注框定位待描述目标；交付模型的训练输入仍是无GT标记原图，Query不引用“红框中的目标”之类制作标记。
- 第二轮核验者只看三图和Query尝试重新定位，再与原框比对。通过不等于绝对正确，人工优先查同类密集、深度空洞和模型分歧。同场景不同帧的相对关系逐帧复核，不能沿时间轴盲复制Query。
- 原始深度单位、无效值与实际三路对应先从样例确认；三路尺寸相同不能代替配准核验。

## 模型与训练

沿用M2第二轮适配器作为低成本继续训练起点，保留原权重作比较；先不全参、不换更大基座、不同时加视觉LoRA。RGB-D/RGB-T/三图数据都使用真实模态和明确对应提示，最终回到三图定位。

两段训练：先用有上限的混合数据学习新的模态/实例任务，再用city和新三模态困难题短程对齐比赛输出。第二段仍保留部分新数据，不把刚学到的辅助模态能力完全用旧简单题覆盖。第一轮以混合数据1轮＋目标域短程1轮作能力检查，按实际每轮准确率与稳定吞吐决定后续，不先固定大规模遍历。

任务比例可从直接BBox约80%、实例选择/可靠近远及跨模态判别约20%起步。辅助题仍使用简短、可核对答案，不生成长思维链。比例是实验起点。相对旧M2增加新任务应与同初始化、同更新数的普通定位继续训练比较，不能把多跑步数当新算法收益。

若干净混合数据仍不能带来真实模态增益，再做小规模视觉适配；当前视觉全冻结是剩余的明确假设，但不必在验证数据路线前同时修改它。

## 并行小实验

从真实RGB和IR候选中读取可靠对象深度，比较无深度对象表与有可靠深度关系的选择结果；候选缺失仍计失败。若真实候选覆盖或选择收益不足，不先训练重排序器。先用原始RGB上下文和必要IR细节，避免每题八组裁剪暴涨计算。
