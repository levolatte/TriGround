## 3. 赛题的精确定义

### 3.1 任务本质

这是 Referring Expression Comprehension（指代表达理解，REC）/ Visual Grounding（视觉定位）任务，而不是普通闭集目标检测：

- 输入自然语言 Query，描述目标的外观、形状、位置、动作或关系；
- 输入一组空间对齐的 RGB、热红外、深度图；
- 每条 Query 在 RGB 图像中唯一指向一个目标；
- 输出该目标在 RGB 图像坐标系中的单个边界框。

一组图像可以对应一条或多条 Query。因此“图像组”与“评测样本”不是完全同义：ACC@0.5 的分母是 Query 样本数，而不是唯一图像组数量。

### 3.2 四种输入模态

| 模态 | 官方格式 | 语义与注意事项 |
|---|---|---|
| RGB | 三通道 `uint8`，范围 `[0,255]` | 目标框最终定义在该图像坐标系；原图未归一化 |
| Infrared | 三通道 `uint8`，范围 `[0,255]` | 三通道视觉特征高度一致，本质是热辐射灰度图重复堆叠；值越高越热、越亮 |
| Depth | 单通道 `uint16`，理论范围 `[0,65535]`，单位毫米 | 相机约可感知 0.3-20 米；有效数据约在 `[0,19999]`；0 或过小为无效深度；值越大越远 |
| Query | 英文句子 | 描述目标属性、位置、行为、数量、关系或指代信息 |

官方声明三种视觉模态已经人工空间对齐，但没有明确说明：

- 三种图是否始终具有相同像素尺寸；
- 是否存在固定裁剪、边缘空区或残余标定误差；
- 深度无效值的实际比例和传感器噪声分布。

这些都需要从示例数据和正式数据统计确认，不能只凭规则假定。

### 3.3 标签与输出

每条 Query 的目标框格式固定为：

```text
[x1, y1, x2, y2]
```

其中：

- `(x1, y1)` 为左上角；
- `(x2, y2)` 为右下角；
- x 坐标除以 RGB 图宽，y 坐标除以 RGB 图高；
- 四个值必须位于 `[0,1]`；
- 预测框必须满足 `x1 < x2` 且 `y1 < y2`。

评测 JSON 以 Query ID 为键，包含 `visible`、`infrared`、`depth`、`query`、`bbox`。提交时只能改 `bbox` 字段；其他字段的任何改动都可能导致评测匹配失败。

以下预测会直接判无效：

- 反向坐标；
- 越界坐标；
- NaN；
- 无效空框。

最终预测 JSON 需要压缩为 ZIP 后上传。

## 4. 指标及其比赛含义

唯一明确的主指标是 ACC@0.5：

```text
ACC@0.5 = count(IoU(pred, gt) >= 0.5) / number_of_queries
```

这意味着：

1. 每条 Query 只有“过 0.5”或“不过 0.5”两种贡献，不会因为 IoU 从 0.7 提升到 0.9 得到额外主指标收益；
2. 候选排序错误通常比框边界的小幅误差更致命；
3. 框尺度、中心偏差和后处理校准仍然重要，因为它们会决定边缘样本能否跨过 0.5；
4. 必须按 Query 类型、目标尺寸、遮挡、模态质量做分组 ACC@0.5，而不能只看平均 IoU；
5. 官方保留将低于其公开 Baseline 的提交认定为无效成绩的权利，所以“能运行”不等于有效参赛结果。

## 10. 已学习的相关技术与可复用资源

### 10.1 Grounding DINO / MM-Grounding-DINO

Grounding DINO 可接受类别名或 referring expression（指代表达）并输出框，采用视觉-语言特征增强、语言引导查询选择和跨模态解码器。官方实现为 Apache-2.0 许可。

更值得后续实验关注的是 MM-Grounding-DINO：

- 公开了完整训练与评测流程；
- 原生覆盖 OVD（开放词汇检测）、PG（短语定位）和 REC；
- 支持 RefCOCO/+/g、Flickr30K Entities、GQA 等定位数据；
- 支持自定义数据微调；
- 有可复现配置和模型权重。

一手资料：

- https://github.com/IDEA-Research/GroundingDINO
- https://arxiv.org/abs/2303.05499
- https://arxiv.org/abs/2401.02361
- https://github.com/open-mmlab/mmdetection/tree/main/configs/mm_grounding_dino

### 10.2 Qwen3-VL

Qwen3-VL 官方支持更强的 2D Grounding（二维定位）、空间关系判断和多图输入，并提供正式微调框架。其 2D 定位采用相对坐标，官方训练示例输出 JSON 边界框；当前官方 8B Instruct 权重为 Apache-2.0。

但不能把“具备定位能力”理解成“直接输出框就足够稳定”。CVPR 2026 GroundingME 在同样使用 Accuracy@0.5 的困难视觉定位测试上显示，开源榜首 Qwen3-VL-A22B Thinking 总分为 49.8，Qwen3-VL-8B Thinking 为 34.3；相似目标、复杂空间关系、遮挡和小目标仍是明显短板。该 benchmark 与本赛题分布不同，数值不能直接当作预期比赛成绩，但足以说明必须实测，不能迷信模型规模。

一手资料：

- https://github.com/QwenLM/Qwen3-VL
- https://github.com/QwenLM/Qwen3-VL/tree/main/qwen-vl-finetune
- https://huggingface.co/Qwen/Qwen3-VL-8B-Instruct
- https://groundingme.github.io/

### 10.3 RGBDT500 / RDTTrack

RGBDT500 是与本题模态最接近的公开资源：500 个 RGB-D-T 视频序列、203.7K 组对齐图像、至少 66 类目标和 100 多种场景。RDTTrack 使用预训练 RGB 跟踪基础模型，把热红外与深度在约束下融合，再作为提示注入 RGB 分支。代码为 MIT 许可。

它是跟踪任务，不是文本视觉定位任务，所以不能直接当作比赛解法；但其数据、传感器分布和三模态处理经验具有很高研究价值。

一手资料：

- https://xuefeng-zhu5.github.io/RGBDT500/
- https://papers.nips.cc/paper_files/paper/2025/hash/b4962fcd5d4410a9f43ef70f528eedd8-Abstract-Datasets_and_Benchmarks_Track.html
- https://github.com/xuefeng-zhu5/RDTTrack

## 12. 可供讨论的比赛假设（不是架构决定）

以下只代表值得验证的实验假设，尚未决定具体模型组合、模块边界或代码结构：

1. **RGB 强基线假设**：先测强视觉定位模型在 RGB 上的零样本和公开数据微调能力，才能量化红外和深度带来的真实增益。
2. **查询类型差异假设**：属性描述、空间关系、距离/远近、序数、动作、计数和指代很可能需要不同能力；平均分会掩盖主要短板。
3. **RGBDT500 迁移假设**：同作者、同模态和相近场景可能带来较强分布迁移价值，但必须先验证示例数据是否同源。
4. **辅助模态条件增益假设**：热红外和深度不一定对所有样本都有利，可能主要改善弱光、遮挡、距离、尺寸和外观相似样本；应通过分组消融确认。
5. **直接生成坐标风险假设**：Qwen3-VL 直接生成框与定位模型候选框两种范式都需要在相同数据上比较，不能仅凭公开宣传选定。
6. **阈值指标校准假设**：围绕 IoU 0.5 的框尺度和候选置信度校准，可能比提升高 IoU 样本更直接地增加比赛分数。
7. **阶段分布漂移假设**：初赛、复赛、半决赛可能逐步增加关系推理和模态缺陷难度，单一阶段排行榜最优配置未必能直接迁移。

## 13. 建议优先讨论的决策

在设计架构前，建议团队先讨论并确认：

1. 是否立即获取并做只读统计审计的官方示例数据；
2. 是否把 RGBDT500 作为第一批外部训练/预训练数据候选；
3. 本地 8GB 显存与可用云算力预算，以及测试数据允许进入何种计算环境；
4. 第一轮要对比的最小 Baseline 清单及统一评测协议；
5. 三位成员如何分配数据审计、定位基线、多模态研究和实验记录责任；
6. 如何保存每个实验的假设、配置、ACC@0.5、分组结果和结论。

明确不在本轮决定的事项：最终架构、训练框架、融合层位置、模型规模、仓库代码结构和部署形式。
