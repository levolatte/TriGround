# G/U未提分的根因调查与路线反思

2026-09-26。范围：真实云端训练清单、消费顺序、人工放行记录、全部412条预测、三模态原图及相关论文。仅CPU审计和研究；精确取回云端已有3组12张缺图用于补审，未启动新训练、模型推理或自动化，未修改原始标签及人工决定。

## 1. 结论先行

**目前最有证据的问题是：我们把大量工作投入了“对象在多张图中的对应”，实际提供给模型的“辅助模态解决目标歧义”监督很少。训练工程基本按计划执行，但实验没有充分覆盖用户真正希望获得的能力。**

这能解释为什么不能期待本轮明显释放Depth/IR的作用，却还不能精确证明U少掉的5题由哪一个因素造成。必须区分三个层次：

1. **已证实的目标偏差**：本轮没有训练近远比较、层级排序或基于层级选择目标；实际新数据仅98条不同Query，绝大多数是对象对应。
2. **已观察到的行为变化**：框边界普遍有小变化，部分实例区域改变；U比G少5个命中，但平均IoU反而略高。不是模型全面失去定位能力。
3. **尚未识别的机制**：视觉特征适配不足、任务梯度干扰、借RGB几何完成辅助答案、提示变化的影响，都有合理依据，但目前没有本地因果实验足以确认。

没有发现“一修就能恢复全部成绩”的确定工程故障。也没有证据支持放弃三模态或继续盲目增加同类框标注。

| M2同机基线 | 285 | 0.59833 | — | −7 |
| C1500 | 292 | 0.61363 | +7 | — |
| G100 | 284 | 0.59531 | −1 | −8 |
| G200 | 288 | 0.59441 | +3 | −4 |
| U100 | 283 | 0.59682 | −2 | −9 |
| U200 | 283 | 0.59621 | −2 | −9 |

这些都是内部City开发集，不是新官方成绩。M2/C官方同为0.7144来自用户反馈；G/U未跑官方测试。

G/U同样从M2出发，固定200更新；G也是三模态输入，只是全部输出RGB框。U相对G纠正1条、退化6条，净−5。C多训1500更新，训练分布也不同，不能将“比C低”直接解释成新增数据造成的因果损害；它说明新候选没超过现有较强方案。

按78图组、10000次重采样，G相对M2的ACC差区间为−0.73至+2.16个百分点，U为−1.87至+0.80，均跨0；U相对G为−2.75至0.00。单seed、反复开发的同一验证集限制了结论，不能宣布跨模态监督普遍有害。另一方面，平均IoU和ACC@0.7均未改善，因此也不能把所有问题简单归为随机波动。

## 3. 制作量很大，但有效训练信息没有等比例增加

### 3.1 从制作到本轮训练的实际漏斗

| 环节 | 实际数量 | 不能混称的内容 |
|---|---|---|
| RGBDT首轮检查 | 200图组、138自然Query | 检查过不等于合格训练题 |
| 机器暂通过 | 252个输出任务 | 同一Query可派生RGB/IR/Depth多个框 |
| 两包人工检查 | 200检查项 | 不是200条独立Query |
| 实际放行并入训 | 181输出：RGB98、IR58、Depth25 | 对应98条Query、98图组 |
| 每组训练新数据呈现 | 400次 | 181任务重复，不是400新题 |
| U额外输出监督 | IR128次、Depth55次 | 占全1600呈现的8.0%、3.44% |

RGBT6000、Robo2000、City扩展、后来新增RGBDT40的制作成果，都没有进入本轮181任务版本。不能把“磁盘已有数千条”当成此次实验已使用数千条；也不能把几种输出相加成几倍独立场景。

98条用于一次低成本方法探针本身是合理的，不能因为结果不好就事后要求数千条才算数。这里的问题不是“少于某个数量一定无效”，而是这98条主要提供哪种信息、与要改进的错误是否对应；增加相同类型数据也不会自动补上关系标签。

### 3.2 真正的互补信号非常少

对98条实际放行Query与既有证据分类逐ID连接：81条属于“仅对应”，5条属于“互补候选”，12条只有RGB可用。这里是既有证据清单分类，不是本次对98条全部重新做独立模态对照，更不是5条已证明模型必须使用辅助图。

400次新呈现中，这5条候选共呈现19次，其中IR输出8次、Depth输出0次。**本轮没有足够的事实依据被称为一次深度层级能力训练。**

还存在明确的监督预算取舍：G的1600次呈现都监督最终RGB框；U将其中183次改为辅助图框，直接RGB输出监督剩1417次。U的跨模态监督是在固定预算内替换直接任务，并非在保持全部直接训练后免费增加。若辅助任务迁移价值低，这种取舍可能不划算；目前尚不能定量归因5题差额。

辅助框与RGB框的归一化IoU中位数：IR约0.821、Depth约0.761。这样的标签可以教对象对应，但也允许模型先靠RGB找对象，再利用几何位置近似回答。这个潜在捷径不表示制作者复制了框，也不能证明模型确实如此作答；它说明当前任务并不强制学会我们想教的能力。

### 3.3 数据难度与比赛瓶颈并不贴合

新98个RGB目标的归一化框面积中位数约0.02039；本轮City的1124条不同任务约0.00698。最短边不足图像尺寸3%的目标，新数据为5/98，City为267/1124。新补的目标整体更大，未集中覆盖City里大量微小目标与近邻实例。

独立图组ID也不等于独立场景。目视已确认至少268/269跑步、369/370小动物两对属于相同机位背景；不能把98图组直接宣传为98种新场景，也不能凭两对外推全部重复比例。跟踪序列的多个编号需要场景层面的重新计数。

RGBDT500本身不是坏数据，但它是跟踪数据：对象已由首帧目标定义，未天然提供完整竞争对象和语言约束。有三路图像不代表每一帧都有可靠的前后层级差。这一点与[RGBDT500原论文](https://proceedings.neurips.cc/paper_files/paper/2025/file/b4962fcd5d4410a9f43ef70f528eedd8-Paper-Datasets_and_Benchmarks_Track.pdf)的任务定位一致。

### 3.4 深度不是被本轮代码错误渲染，但可用信息有局限

数据审计逐像素核对98张本地训练Depth渲染、原始raw公式与人工页面预览，结果一致；原16位图最大值均不超过19999，其中86张达到19999，固定20000映射没有引入额外上界截断。原数据是否更早经历饱和或其他编码变换，本次不能据此排除。

原始0编码占比整图中位24.18%，13/98张超过50%；25个Depth目标框内部的0编码中位19.02%。处理程序把0显示为无效黑色，但原始编码语义仍需来源确认。框内含背景，不能直接把这个比例当主体有效率；没有依据认定全数据深度失效。

更关键的是：本地RGBDT数值方向/物理单位尚不充分确定，正确做法是避免编造近远标签。错误在于后续仍将这批主要对应数据当成“深度推理主力”，而没有及时转向已确认含义、主体层级清楚的数据。

## 4. 代码、训练、评分逐层核对

| 核查 | 发现 |
|---|---|
| 初始化 | 两组均从指定M2适配器初始化；预检核对288个LoRA张量，新建优化器 |
| 数据与顺序 | 1600条实际成功训练消费轨迹逐ID一致，三张图片与次序一致 |
| 调度与恢复 | 总计划始终200更新；100处完整恢复，无100步调度重新开始的迹象 |
| 标签与输入 | 输出模态明确，框为0–1000坐标；RGB/IR/Depth图像列未对调 |
| loss与截断 | 预检代表样本答案被监督、未截断；日志有限，无数值故障；没有把代表8条夸成全1600逐token证明 |
| 评估 | M2/C/G/U的412条提示、图片、GT逐项一致，均使用同一目标版本 |
| 解析 | 全部成功、无128 token截断；独立重算IoU无命中状态差异 |

**发现了一个真实对照混杂因素：** U的183条辅助呈现不仅改变了输出模态/坐标，还采用不同提示模板，并省略G提示中的深度编码说明。下次应统一模板，除必要输出模态指令外保持一致。当前不能证明这导致了降分，也不能期待改一句提示就解决全部问题。

视觉编码器和连接模块全部冻结，只训练语言注意力LoRA，这是既定配置，不是执行错误。它可能限制非RGB表示适配，也可能足够完成小规模迁移；当前没有分模态诊断，不能直接裁定“冻视觉就是根因”。没有记录或分析注意力、模态梯度夹角，不声称已经看到了模态忽略或任务冲突。

细节和代码定位见[代码独立审计](2026-09-26-gu-code-root-audit.md)。

## 5. 错误究竟发生在哪里

全412条比较发现，G/U相对M2的框面积中位比为0.966/0.979，中心位移中位约0.00071。预测大多仍在相同区域，框边界有轻微系统变化，另有少数实例区域改变。

U与G的401/412个预测框相互IoU至少0.7；U有162条连续IoU提高、110条降低，其余近乎不变。平均IoU高0.00180却少5个ACC命中，说明阈值附近分布改变，不支持“U普遍更不会选对象”的说法。

| 实例 | G IoU → U IoU | 原图支持的解释 |
|---|---:|---|
| 远处小船 `city_000081_006` | 0.5026→0.4947 | 很小的框界差跨过0.5 |
| 红色桨板左侧的人 | 0.5178→0.4917 | 同目标附近范围改变 |
| 打电话的右侧访客 | 0.5023→0.4255 | 框边界扩大；辅助图清晰度有限 |
| 重叠斑马 | 0.6504→0.4948 | G较宽、U较窄；原GT范围跨重叠区域，目标范围存在不确定性 |
| 灌木右方暗色目标 | 0.3923→0.5431 | U反而改善 |

相对C还存在灯柱、顶灯、动物和邻近访客等选错邻居的情况，不能全部解释成边界误差。反过来，只看ACC翻转也会漏掉双方都错但错误对象改变的样本，例如 `city_000019_038_00000205_007` 从GT附近转到右侧另一位访客，IoU由约0.450到0。

坐标整数化也被单独检验：理想GT四舍五入到千分位再还原，412条仍全部命中，最低IoU约0.853。量化对小目标更敏感，但不足以解释本次整体变化；不能据此改比赛阈值或修改GT。

几何统计覆盖全412条，视觉审查覆盖既有30例图册，并额外补审12条。C与G/U预测框相互IoU低于0.5的20条并集，现已20/20原图目视。新增12条中，3条为同一错误候选区域内的小框位移、3条为相邻目标区域改选、2条为不同对象/结构、4条涉及密集实例或语义/组合框范围争议；不能将目的抽样频率当全验证集比例。小框只移动十几像素也可能彼此IoU很低，不能自动判定换了对象。

完整统计与可复算脚本见[结果独立审计](2026-09-26-gu-outcome-root-audit.md)，补充逐例证据见[12条目视记录](../../results/gu_pilot_20260926/low_agreement_review12/visual_review.md)。

## 6. 论文给出的共同方向

本次使用24个不同检索问题，覆盖作者仓库、arXiv、CVF、NeurIPS，保留15项主要工作及1项补充。按任务相关性阅读，而非用论文数量证明结论。[完整论文审阅表](2026-09-26-gu-root-cause-literature.md)区分正式发表和预印本、资源成本及不可外推的边界。

最值得借鉴的不是换更大基座，而是以下三条：

1. **把“对应”和“关系”分开训练、分开验收。** [SpatialRGPT](https://arxiv.org/html/2406.01584v3)通过对象区域与空间关系构建监督；[SpatialBot](https://arxiv.org/html/2406.13642v3)区分深度读数、对应和关系应用。这与只框出Depth里的对象有本质差别。前者还使用深度连接器，不能将其效果全算作数据收益。
2. **辅助传感器可能需要适配，而非仅添加一张图片。** [RGBT-GroundBench](https://arxiv.org/html/2512.24561v2)的MLLM实验不支持直接附加TIR总会提分，专用模型使用模态适配与交互；[Thermo-VL](https://arxiv.org/html/2605.21882v1)研究保留RGB主干、让热红外补充信息。后者是预印本问答任务，不能直接承诺本比赛定位收益。
3. **语言理解和精确框回归可以分别诊断。** [VGent](https://arxiv.org/html/2512.11099v1)提供语义理解与候选定位分工的参考；[Qwen3-VL技术报告](https://arxiv.org/html/2511.21631v1)也将定位与空间关系数据分开建设。先确认我们的实例选择与框界各占多少问题，再决定使用真实候选或预测触发的局部细化。

模态主导、共享任务干扰等论文提供机制假设，不提供本轮因果证明；不据此马上增加梯度算法、强化学习、模型融合或昂贵架构。

## 7. 我需要修正的工作流

1. **优先级错位。** 花了大量时间提高跨模态框的制作和审核完整性，却较晚检查这些题是否真的提供新的决策信息。标注正确与对比赛有帮助是两个不同问题。
2. **进度口径容易掩盖信息量。** 图组、对象、Query、分模态输出、重复呈现曾并列汇报；这些不是等价样本。今后核心进度应为“可靠关系/互补场景、独立Query、最终RGB定位任务”，对应框单列。
3. **没有及时承认Depth主线缺料。** 数据单位不明不能造标签是正确约束，但这应触发换数据/换可靠关系来源，而非不断生产左右描述或对应框来代替层级题。
4. **实验识别能力不足。** 本轮G/U配对很严格，但提示变化未完全固定；缺少同预算City对照和辅助任务自身学习诊断。C1500不能代替City200。
5. **工程预检不能代替能力预检。** 梯度、恢复、解析通过只证明能训练；不证明新任务学会，也不证明学到的内容依赖辅助模态。

用户的人工作业没有浪费：它排除了错误/歧义标签，并留下可复用的对象对应库。但应明确，它验证的是标签质量，不负责验证我选的训练目标是否有用。

## 8. 建议的最小下一步：先鉴别，不再盲扩量

以下是本次调查提出的建议，**未执行新GPU实验，不自动恢复已停止的训练计划。**

### A. 先用现有M2/G/U检查点区分“没学会”和“学会但没帮助”

- 对已有人工确认的对应任务，分别看RGB/IR/Depth输出是否改善；训练内样本只叫拟合检查，不能作泛化成绩。
- 固定一小份与这些训练图组隔离、可核查辅助证据的自然诊断集，比较正确提示下的RGB、RGB+IR、RGB+Depth、三模态输入。记录每条辅助线索实际解决了哪个歧义。
- 单纯去掉模态产生输入分布变化，因此模态组合差异仍需谨慎解释；错配/黑图只做额外扰动诊断，不能替代自然比较。
- 若辅助输出都没有学会，先查任务量、输入表达和表示适配；若辅助输出改善而RGB定位不改善，优先改任务目标；若RGB已经可解且辅助没提供新信息，优先改选样。

### B. 新训练题优先输出比赛真正需要的RGB框

- 深度题建立“确认主体区域→读取可靠原深度→比较前后层级→按Query选对象→输出RGB框”的链条。主体取样避开地面和背景；近远差有可靠依据才派生。
- IR题必须能具体说明它补足了RGB的哪个不确定点；普通IR框对应仍保留，但不再作为互补能力完成数。
- 对同场景不同目标的实质性Query可成对构造，答案必须随约束变化；不以同义改写凑量，不强制每题必须依赖三路。
- 首轮只制作能支持小试验的高信息量集合，不再先追求6000–10000任务。继续扩大必须由固定自然诊断和完整412定位共同支持。

### C. 再根据诊断选一个最小改动

| 诊断结果 | 优先动作 | 暂不做 |
|---|---|---|
| 辅助任务未学会 | 统一提示，检查辅助拟合；必要时小范围视觉/连接器适配实验 | 直接换大模型或加上千步 |
| 辅助任务学会但最终定位无收益 | 改为关系决定目标、最终RGB框监督 | 继续堆同类对应框 |
| 实例基本对但边界成为主要损失 | 预测触发的局部框细化，另测覆盖与完整定位 | 按GT裁剪或验证集调全局扩框 |
| 相邻实例确实难分 | 真实检测候选+可靠关系选择；先测真实候选覆盖 | 用GT候选冒充端到端结果 |

如要再次训练，固定同一提示、数据顺序、200步预算，并增加相同预算的City参照以区分常规继续训练漂移。这个参照仍同时改变新增来源及City暴露量，应按实际对照含义解释。确认方向后才第二seed；本轮已批准的扩大门槛失败，不能自动重启600/1500。
